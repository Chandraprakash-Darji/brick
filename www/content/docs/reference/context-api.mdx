Brick-TS uses Effect's **`Context.Service`** pattern for dependency injection, eliminating untyped ambient bags and global state.

## Defining Services (`Context.Service`)

Create a service tag by extending `Context.Service`:

```ts title="src/services/logger.ts"
import { Context } from "effect";

export interface LoggerService {
  readonly log: (message: string) => void;
}

export class AppLogger extends Context.Service<AppLogger, LoggerService>()(
  "AppLogger",
) {}
```

## Requiring Services in Action Handlers

In any action handler, access the service using `yield*`:

```ts
const myAction = MyAction(() =>
  Effect.gen(function* () {
    const logger = yield* AppLogger;
    logger.log("Executing action...");
    return { success: true };
  }),
);
```

TypeScript automatically adds `AppLogger` to the Effect's requirement channel (`R`).

## Providing Services with Layers

Create a `Layer` implementing the service:

```ts
import { Layer } from "effect";

export const LoggerLive = Layer.succeed(AppLogger, {
  log: (msg) => console.log(`[APP] ${msg}`),
});
```

Combine all service layers and supply them to `Brick.app({ layer })`.

## Request-Level Context (`HttpServerRequest`)

To access request-specific information (such as HTTP headers or client IP), read the `HttpServerRequest.HttpServerRequest` service provided automatically by Brick's HTTP server:

```ts
import { HttpServerRequest } from "effect/http";
import { Effect } from "effect";

const whoami = WhoamiAction(() =>
  Effect.gen(function* () {
    const request = yield* HttpServerRequest.HttpServerRequest;
    const userAgent = request.headers["user-agent"] ?? "unknown";
    return { userAgent };
  }),
);
```
