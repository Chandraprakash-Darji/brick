`Brick.app` is the primary entry point for composing and scoping an Effect-native application.

## `Brick.app` Options Table

| Option           | Type                                      | Default       | Description                                                                              |
| :--------------- | :---------------------------------------- | :------------ | :--------------------------------------------------------------------------------------- |
| `services`       | `readonly ServiceConstraint[]`            | _(Required)_  | Array of immutable services created with `Brick.service()`.                              |
| `layer`          | `Layer<AppRequirements, E, never>`        | _(Required)_  | Closed Effect Layer supplying all required services for handlers, routes, and stores.    |
| `routes`         | `Layer<RoutesA, RoutesE, RoutesR>`        | `Layer.empty` | Optional custom HTTP routes defined with `Brick.route()`.                                |
| `docs`           | `{ path: '/${string}' }`                  | `undefined`   | Mounts interactive Scalar API documentation at the specified path (e.g. `"/reference"`). |
| `client`         | `{ module: string, exportName?: string }` | `undefined`   | Configures the client contract module relative to entry for `brick gen client`.          |
| `transports.rpc` | `{ path: '/${string}' }`                  | `undefined`   | Configures native JSON-RPC transport route.                                              |
| `transports.mcp` | `McpServerOptions`                        | `undefined`   | Configures native Model Context Protocol HTTP/SSE server for AI agents.                  |

## Validation Rules

During application composition:

1. **Service Names**: Duplicate service names throw an error.
2. **Action Paths**: Duplicate HTTP method + path routes throw an error.
3. **Action Keys**: In `Brick.service("name", { actions })`, each key must strictly equal its action's `endpoint.identifier`.
4. **Compile-Time Dependencies**: The supplied `layer` must resolve all requirements (`R`) from all actions in all mounted services. Missing requirements trigger TypeScript compiler errors.

## Application Instance Properties

`Brick.app` returns an immutable application object exposing:

| Property   | Type                                      | Description                                                             |
| :--------- | :---------------------------------------- | :---------------------------------------------------------------------- |
| `kind`     | `"brick-native-app"`                      | Discriminator literal for native Brick applications.                    |
| `services` | `readonly ServiceConstraint[]`            | Frozen array of all mounted services.                                   |
| `api`      | `HttpApi`                                 | The compiled Effect `HttpApi` instance.                                 |
| `layer`    | `Layer`                                   | The closed routing layer.                                               |
| `fetch`    | `(request: Request) => Promise<Response>` | Web-standard Fetch handler for Bun, Node, or Cloudflare Workers.        |
| `ready`    | `() => Promise<void>`                     | Initializes startup layers and verifies application readiness.          |
| `dispose`  | `() => Promise<void>`                     | Gracefully interrupts active fibers and closes the application `Scope`. |
| `openApi`  | `() => OpenApiDocument`                   | Generates the OpenAPI 3.1 schema representation of the application.     |
