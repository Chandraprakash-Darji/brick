---
title: Error Reference
description: Declared native HTTP and CRUD error schemas and status code mapping.
---

Brick-TS uses Effect's **`Schema.TaggedError`** system for all domain failures. Every error has a distinct `_tag`, a typed payload, and an annotated HTTP status.

## Core Error Catalog (`@brickkit/core/contracts`)

| Error Class           | HTTP Status | Message Shape         | Usage                                                              |
| :-------------------- | :---------- | :-------------------- | :----------------------------------------------------------------- |
| `BadRequest`          | 400         | `{ message: string }` | Request payload violates business validation or input constraints. |
| `Unauthorized`        | 401         | `{ message: string }` | Authentication is missing, expired, or invalid.                    |
| `Forbidden`           | 403         | `{ message: string }` | Caller is authenticated but lacks required permissions.            |
| `NotFound`            | 404         | `{ message: string }` | Requested resource, row, or entity does not exist.                 |
| `Conflict`            | 409         | `{ message: string }` | Uniqueness constraint violated or duplicate record exists.         |
| `InternalServerError` | 500         | `{ message: string }` | Unexpected backend failure.                                        |

## CRUD Error Catalog (`@brickkit/crud`)

| Error Class       | HTTP Status | Usage                                               |
| :---------------- | :---------- | :-------------------------------------------------- |
| `InvalidInput`    | 400         | Filter operator or mutation field policy violation. |
| `Forbidden`       | 403         | CRUD `authorize` predicate returned `false`.        |
| `NotFound`        | 404         | Primary key not found or row excluded by `scope`.   |
| `Conflict`        | 409         | Unique database constraint or primary key conflict. |
| `DatabaseFailure` | 500         | Database driver error during query execution.       |

## Declaring Custom Tagged Errors

Declare custom domain errors using `Schema.TaggedError`:

```ts title="src/errors.ts"
import { Schema } from "effect";

export class AccountLocked extends Schema.TaggedError<AccountLocked>()(
  "AccountLocked",
  {
    message: Schema.String,
    unlocksAt: Schema.String,
  },
  { httpApiStatus: 403 },
) {}
```

Include `AccountLocked` in the action's `errors` array:

```ts
const myAction = Brick.action("unlock", "/api/unlock", {
  input: Schema.Struct({}),
  output: Schema.Struct({ success: Schema.Boolean }),
  errors: [AccountLocked],
})(() =>
  Effect.fail(
    new AccountLocked({
      message: "Account is temporarily locked",
      unlocksAt: "2026-10-15T14:00:00Z",
    }),
  ),
);
```

The error serializes automatically to JSON with HTTP status 403:

```json
{
  "_tag": "AccountLocked",
  "message": "Account is temporarily locked",
  "unlocksAt": "2026-10-15T14:00:00Z"
}
```
