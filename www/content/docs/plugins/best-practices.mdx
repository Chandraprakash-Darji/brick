---
title: Extension Best Practices
description: Guidelines for building robust, decoupled Effect-native extensions.
---

Follow these best practices when building extensions for Brick-TS.

## 1. Separate Contracts from Implementations

Always split your extension into separate modules:

- `contract.ts`: Pure Effect Schema definitions, `crudContract`, and `Schema.TaggedError` classes. Never import database drivers, file system modules, or server secrets here.
- `index.ts`: The handler factory and store implementation.

This ensures frontend applications can import the contract without pulling database drivers into browser bundles.

## 2. Accept Explicit Dependencies

Do not open database connection pools or instantiate global clients inside module scope. Instead:

- Require dependencies through `Context.Service` tags.
- Let the host application supply the `Layer` during `Brick.app({ layer })`.

This allows consumers to manage connection pooling, transaction boundaries, and scoped disposal.

## 3. Enforce Deny-by-Default Access

When authoring reusable CRUD extensions:

- Expose only the fields that are necessary for the extension to function.
- Require an explicit `access` configuration or default to authenticated access rules.
- Validate and sanitize input in `beforeCreate` and `beforeUpdate` hooks.

## 4. Declare All Error Schemas

Never throw untyped exceptions or return generic strings. Define every domain error as a `Schema.TaggedError` with an `{ httpApiStatus }` annotation:

```ts
export class DuplicateSlug extends Schema.TaggedError<DuplicateSlug>()(
  "DuplicateSlug",
  { message: Schema.String },
  { httpApiStatus: 409 },
) {}
```

Include all error classes in the contract's `errors` array so OpenAPI schemas and client types stay accurate.

## 5. Verify In-Process and Over HTTP

Test extensions both ways:

1. In-process: Calling actions directly as Effects with `Effect.provide(TestDatabaseLive)`.
2. Over HTTP: Starting an application with `brick dev` or `app.fetch()` and testing HTTP requests with curl or fetch.
