---
title: Plugins
description: Install service and resource plugins with typed APIs and scoped routes
---

Use `defineServicePlugin()` to package service capabilities and install them with
`service.use(plugin)`. Use `defineResourcePlugin()` to attach a named API to an
existing resource with `resource.use(plugin)`.

```ts
import { defineService, defineServicePlugin, t } from "@brickkit/core";

const greeting = defineServicePlugin({
  name: "example/greeting",
  setup({ routes }) {
    const hello = routes.action({
      name: "hello",
      method: "GET",
      path: "/hello",
      input: t.Object({ name: t.String() }),
      output: t.String(),
      execute: ({ input }) => `Hello ${input.name}`,
    });
    return { hello };
  },
});

const service = defineService("greetings");
const api = service.use(greeting);
await api.hello({ input: { name: "Ada" } });
```

With the default app prefix, the HTTP route is `GET /api/greetings/hello`.
The generated browser API is `api.greetings.hello`. Local actions use the
same schemas, authorization and execution context as HTTP requests.

A plugin may register raw endpoints for HTML, streams or webhooks. Consumers
can override route paths and scopes or disable HTTP exposure while keeping
local actions callable. Plugins do not create or migrate database tables.

## Other extension points

Resource hooks, `service.action()`, `app.endpoint()`, and `createServiceProxy()`
remain available for application code. Resources are generic table hosts.
Install `@brickkit/crud` with `resource.use(crud({fields: ...}))` for CRUD.
