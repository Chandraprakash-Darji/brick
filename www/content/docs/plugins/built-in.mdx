The core database capabilities of Brick-TS are packaged in `@brickkit/crud`.

## Features

- **Deny-by-Default Security**: Database columns are completely hidden until explicitly opted into via field policies.
- **Composable Stores**: First-class support for SQLite (`sqliteStore`) and PostgreSQL (`postgresStore`).
- **Standard Operations**: Automatically generates `list`, `findOne`, `get`, `create`, `update`, `delete`, `count`, and `exists`.
- **Row-Level Scoping**: Seamlessly combines tenant or ownership SQL predicates with client filters.
- **Lifecycle Hooks**: `beforeCreate`, `afterCreate`, `beforeUpdate`, `afterUpdate`, `beforeDelete`, `afterDelete`.

## Store Architecture

A store in Brick-TS implements the `Store<T, Db>` interface:

```ts
export interface Store<T extends Table, Db> {
  readonly list: (args: {
    where: SQL | undefined;
    order: SQL[];
    limit: number;
    offset: number;
  }) => Effect.Effect<InferSelectModel<T>[], EffectDrizzleQueryError, Db>;
  readonly count: (
    where: SQL | undefined,
  ) => Effect.Effect<number, EffectDrizzleQueryError, Db>;
  readonly create: (
    data: InferInsertModel<T>,
  ) => Effect.Effect<InferSelectModel<T>[], EffectDrizzleQueryError, Db>;
  readonly update: (
    data: Partial<InferInsertModel<T>>,
    where: SQL | undefined,
  ) => Effect.Effect<InferSelectModel<T>[], EffectDrizzleQueryError, Db>;
  readonly remove: (
    id: Column,
    where: SQL | undefined,
  ) => Effect.Effect<unknown[], EffectDrizzleQueryError, Db>;
  readonly transaction: <A, E, R>(
    effect: Effect.Effect<A, E, R>,
  ) => Effect.Effect<A, E | SqlError, R | Db>;
}
```

By decoupling the store from the contract, the exact same CRUD actions can run against in-memory SQLite in test suites and pooled PostgreSQL in production environments.
