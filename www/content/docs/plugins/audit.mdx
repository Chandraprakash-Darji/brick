---
title: Audit trail pattern
description: Record trusted write events in application-owned tables
---

Use CRUD `afterCreate`, `afterUpdate`, and `afterDelete` hooks to record write
events with resolved context. The application owns the audit table and schema.
Hooks belong to `crud({fields,hooks})`, not the core resource declaration.

After hooks run after the write, so a failure does not automatically undo the
write. Use an application transaction when business data and audit rows must
commit atomically. Avoid storing secrets or unmasked payloads in audit records.
Expose audit reads through a separate resource with its own field and access
policies, or through ordinary authorized actions.
