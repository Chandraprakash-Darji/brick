title: Build a plugin
description: Define typed service and resource APIs with controlled HTTP exposure
---

A plugin is a descriptor with a name and a synchronous `setup()` function.
Service plugins return their API. Resource plugins return named contributions
that extend the installed resource. Installation registers declarations before
app build; it does not run migrations or start background tasks.

## A service plugin

This module creates an action and a raw HTML endpoint. The factory owns its
options and forwards route controls to the framework.

```ts
// greeting.ts
import { defineServicePlugin, t, type PluginRoutes } from "@brickkit/core";

export function greeting(
  options: {
    salutation?: string;
    routes?: PluginRoutes<"app" | "service">;
  } = {},
) {
  const salutation = options.salutation ?? "Hello";
  return defineServicePlugin({
    name: "example/greeting",
    routes: options.routes,
    setup({ routes }) {
      const hello = routes.action({
        name: "hello",
        method: "GET",
        path: "/hello",
        input: t.Object({ name: t.String() }),
        output: t.Object({ message: t.String() }),
        execute: ({ input }) => ({ message: `${salutation} ${input.name}` }),
      });
      routes.endpoint({
        name: "help",
        method: "GET",
        path: "/help",
        handler: () =>
          new Response("<p>Send a name to the greeting endpoint.</p>", {
            headers: { "content-type": "text/html" },
          }),
      });
      return { hello };
    },
  });
}
```

```ts
// app.ts
import { defineService } from "@brickkit/core";
import { brick } from "@brickkit/cli";
import { greeting } from "./greeting";

const service = defineService("greetings");
const api = service.use(
  greeting({
    routes: {
      hello: { scope: "app", path: "/welcome" },
      help: false,
    },
  }),
);

export default brick({ services: [service], prefix: "/v1" });
await api.hello({ input: { name: "Ada" } });
```

This exposes `GET /v1/welcome?name=Ada`. The `help` endpoint is disabled.
Action schemas infer the local input/output types and generated browser types.
Raw endpoints have no generated JSON client method.

## Resource contributions

A resource plugin receives the parent resource. The same descriptor can be
installed on multiple resources, with independent registrations and paths.

```ts
import {
  defineDatabase,
  defineService,
  defineResourcePlugin,
  sqliteTable,
  text,
  t,
} from "@brickkit/core";

const pages = sqliteTable("pages", {
  id: text("id").primaryKey(),
  title: text("title").notNull(),
});
const service = defineService("pages", {
  database: defineDatabase({ tables: { pages } }),
});

const identity = defineResourcePlugin({
  name: "example/identity",
  setup({ resource, routes }) {
    const name = routes.action({
      name: "name",
      method: "GET",
      path: "/identity",
      output: t.String(),
      execute: () => resource.name,
    });
    return { identity: { name } };
  },
});

const page = service.resource({ name: "page", table: pages }).use(identity);
await page.identity.name({});
// GET /api/page/identity
// Browser client: api.page.identity.name()
```

Retain the `.use()` return value to use the inferred contributions. Plugins
cannot replace resource properties or existing contributions. The supplied
schema remains application-owned; this declaration does not create tables.

## Route placement and exposure

Route names are stable keys for consumer overrides. Both actions and raw
endpoints accept a scope:

- `service` mounts under the service name and is the service plugin default.
- `resource` mounts under the resource name and is the resource plugin default.
- `app` mounts directly under the configured app prefix.

Service plugins cannot select resource scope. Override a route with
`routes: { hello: { path: "/welcome", scope: "app" } }`, disable one with
`routes: { hello: false }`, or disable all plugin bindings with `routes: false`.
Unknown route keys fail installation. These controls apply to the descriptor's
own routes. Dependencies have their own route controls.

Disabling HTTP exposure leaves actions callable locally. Disabled bindings have
no HTTP fallback route and disappear from OpenAPI and generated browser clients.
Returned actions appear at their API paths in the browser contract. Exposed
actions not returned by setup use their internal scoped action names instead.
Raw endpoints appear in OpenAPI and use the framework's endpoint error handling.
Method/path collisions involving plugin routes fail app construction.

## Typed host requirements

A callback declared before installation cannot infer its context from a later
`.use()` call. Annotate setup with `ServicePluginContext<MyService>` when a
plugin requires a particular service database or custom context. For resource
requirements, use `ResourcePluginContext<MyService, MyResource>`.

```ts
import {
  defineService,
  defineServicePlugin,
  t,
  type ServicePluginContext,
} from "@brickkit/core";

const service = defineService("identity", {
  context: () => ({ user: { id: "demo" } }),
});
type IdentityService = typeof service;

const identity = defineServicePlugin({
  name: "example/current-user",
  setup({ routes }: ServicePluginContext<IdentityService>) {
    const who = routes.action({
      name: "who",
      method: "GET",
      path: "/who",
      output: t.String(),
      execute: ({ ctx }) => ctx.user.id,
    });
    return { who };
  },
});
service.use(identity);
```

Raw handlers receive `{ request, params, query, body, headers, set, ctx }`.
`ctx` is the resolved service context, including database, logger and custom
context fields.

## Installation identity and lifecycle

Reuse a descriptor to reuse its installation on one host. Calling a factory
again creates a different descriptor. Installing a different descriptor with
an already installed name on that host fails, even if the options are equal.
Installing the same resource descriptor on another resource is independent.

Setup may install dependencies with `service.use()`. Cycles fail. Registration
and resource contributions are restored when setup throws. External side
effects and arbitrary user-object mutations are outside that transaction.
Setup must be synchronous, and installation must finish before service build.
Route registrars close after setup.

## CRUD and table behavior

`@brickkit/crud` is a resource plugin. Pass field permissions, hooks, access
policies and route controls to `crud()`; the core resource declaration accepts
only name, table and identifier. Plugins own the policies for their own table.

The runnable `examples/extensions` comments factory is installed with
`resource.use(comments({table}))` and returns a `comments` namespace. It uses
the parent identifier to validate targets and installs CRUD on its explicit
comment table. There is no published comments package.

Plugins can specialize returned types for a host with the exported
`ResourcePluginTypes` and `ResourcePluginAPI` protocol. Ordinary descriptors
infer concrete setup return values without that protocol. The CRUD package uses
the protocol to preserve table-specific field and operation types.
