An extension is a normal TypeScript module that combines Brick resources, actions
and hooks. This example adds comments to a pages service. It lives in
[`examples/extensions`](https://github.com/brick-org/brick/tree/main/examples/extensions).
The code below comes directly from the runnable source files.

## Run the example

From the repository root:

```sh
bun install
bun run --cwd examples/extensions demo
bun run --cwd examples/extensions serve
```

The demo verifies CRUD, trimming, rejection of blank text, and the count action
through compiled HTTP routes and direct calls. The server listens on port 3001;
set `PORT` to change it. Its SQLite database is in memory and resets on restart.

`countComments` action. The write hooks trim text and reject blank bodies with
HTTP 400. The custom action validates its input and output with TypeBox and
counts comments for one target. This module uses SQLite's synchronous Drizzle API.

## Use the routes

```sh
curl -X POST http://localhost:3001/api/comment \
  -H 'content-type: application/json' \
  -d '{"targetId":"page-1","body":"Hello Brick!"}'
curl 'http://localhost:3001/api/comment?targetId=page-1'
curl 'http://localhost:3001/api/comments/count?targetId=page-1'
```

The resource also exposes `GET`, `PATCH` and `DELETE` at `/api/comment/:id`.
The demo's `src/main.ts` exercises these routes and calls `countComments` directly
in process using the same action definition.

These example routes are public. Add authentication and ownership policies in
the consuming application's context and resource configuration when required.

## Reuse the extension

Copy the `src/extensions/comments` directory or publish it as a normal npm
module. Consumers import its table and setup function, include the table in their
database, and call `registerComments(service)`. No plugin interface or plugin
registry is required.
