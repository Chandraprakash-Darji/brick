---
title: Comments plugin pattern
description: Attach comments to an explicit parent resource
---

An application comments factory returns `defineResourcePlugin({name,setup})`.
Setup receives `{resource,service,routes}`. The resource supplies the parent
identity; options supply the comment table and typed column mappings. Field
policies belong to comments options and apply to comments, never the parent.

```ts
const page = service
  .resource({ name: "page", table: pagesTable, id: pagesTable.id })
  .use(comments({ table: pageCommentsTable }));
const post = service
  .resource({ name: "post", table: postsTable, id: postsTable.id })
  .use(comments({ table: postCommentsTable }));
```

These are application-defined factories and schema imports. Brick does not ship
a comments package. See the runnable `examples/extensions` implementation for a
concrete single-table factory, target validation, CRUD field policies, write
normalization, and a returned comments namespace.

A reusable factory should accept mapped target/body/author columns, validate
compatible target IDs and authorization, and expose stable named routes. Separate
comment tables per parent permit database foreign keys. Shared polymorphic storage
requires an explicit discriminator and scoping on every operation.
