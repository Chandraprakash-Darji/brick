---
title: CLI Overview
description: Command-line developer and build tooling for Effect-native Brick applications.
---

The `brick` CLI ships with `@brickkit/cli` to provide development live reload, production servers, ahead-of-time bundling with Bun, and client contract generation.

## Installation

Install `@brickkit/cli` alongside `@brickkit/core`:

<Tabs items={["bun", "pnpm", "npm"]}>
  <Tab value="bun">

```bash
bun add @brickkit/cli @brickkit/core
```

  </Tab>
  <Tab value="pnpm">

```bash
pnpm add @brickkit/cli @brickkit/core
```

  </Tab>
  <Tab value="npm">

```bash
npm install @brickkit/cli @brickkit/core
```

  </Tab>
</Tabs>

Run commands with `bunx brick` or add them to your `package.json` scripts:

```json title="package.json"
{
  "scripts": {
    "dev": "brick dev src/app.ts --port 4000",
    "start": "brick start src/app.ts",
    "build": "brick build src/app.ts --outdir dist/brick",
    "gen:openapi": "brick gen openapi src/app.ts --output openapi.json",
    "gen:client": "brick gen client src/app.ts --output src/_brick/contract.ts",
    "info": "brick info src/app.ts"
  }
}
```

## Command Summary

| Command             | Arguments & Flags                            | Description                                                                |
| :------------------ | :------------------------------------------- | :------------------------------------------------------------------------- |
| `brick dev`         | `[entry] [--port <number>]`                  | Start local development server with file watching and live reload.         |
| `brick start`       | `[entry] [--port <number>]`                  | Start production server without file watchers.                             |
| `brick build`       | `<entry> [--outdir <dir>] [--port <number>]` | Bundle a default-exported `Brick.app` into a standalone Bun server bundle. |
| `brick gen openapi` | `<entry> [--output <file>]`                  | Generate OpenAPI 3.1 JSON specification from services.                     |
| `brick gen client`  | `<entry> [--output <file>]`                  | Generate typed browser client contract file (`_brick/contract.ts`).        |
| `brick info`        | `<entry>`                                    | Introspect services, routes, and metadata from the application.            |
| `brick migrate`     |                                              | Run database migrations.                                                   |

## Port Resolution Rules

For `dev` and `start`, the listening port is resolved in strict precedence order:

1. **CLI Flag**: `--port <number>` (e.g. `brick dev --port 5000`)
2. **Environment Variable**: `PORT` (e.g. `PORT=3000 brick dev`)
3. **Default**: `4000`

Port values must be valid integers between `1` and `65535`. Out-of-range values or non-numeric strings cause the CLI to exit immediately with an error.
