---
title: Access control
description: Authorize operations and constrain rows on the server
---

CRUD accepts `access.authorize({operation,input,ctx})` and
`access.scope({operation,ctx})`. Authorization runs for both HTTP and local calls.
A scope returns a trusted Drizzle SQL predicate combined with user filters using
AND. Get, list, findOne, count, exists, update and delete use the same scope.
Rows outside the scope behave as missing for key operations.

```ts
crud({
  fields: {
    id: { read: true },
    title: { read: true, create: true, update: true },
  },
  access: {
    authorize: ({ ctx }) => Boolean(ctx.user?.id),
    scope: ({ operation, ctx }) =>
      operation === "create" ? undefined : eq(pagesTable.userId, ctx.user.id),
  },
  hooks: {
    beforeCreate: ({ data, ctx }) => {
      data.userId = ctx.user.id;
    },
  },
});
```

The fragment assumes a service context with authenticated `user`, `pagesTable`
containing `userId`, and `eq` imported from core. A reusable plugin can annotate
its context constraints. INSERT has no WHERE scope. A nonempty create scope is
rejected; use explicit create authorization and a trusted hook that assigns the
owner. Never allow a caller to submit ownership just to satisfy a scope.

Field read permissions and response masking supplement row policies. They do
not replace authorization. Service auth metadata alone does not enforce access;
configure the CRUD policy or ordinary action authorization explicitly.
