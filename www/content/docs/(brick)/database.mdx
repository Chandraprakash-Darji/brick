Brick-TS pairs Drizzle ORM with Effect's scoped resource management, providing type-safe database access for SQLite and PostgreSQL with guaranteed lifecycle disposal and clean migration paths.

## Minimal Example

Configure an in-memory SQLite database service and provide it to your application via an Effect Layer:

```ts title="src/database.ts"
import { database, sqliteStore } from "@brickkit/crud";
import { sqliteTable, text } from "drizzle-orm/sqlite-core";
import { drizzle } from "drizzle-orm/libsql";
import { Effect } from "effect";

// 1. Declare schema with Drizzle
export const users = sqliteTable("users", {
  id: text("id")
    .primaryKey()
    .$defaultFn(() => crypto.randomUUID()),
  email: text("email").notNull().unique(),
});

// 2. Define scoped database service and Layer
export interface AppDatabase {}
export const { Service: Database, layer: DatabaseLive } =
  database<AppDatabase>()(
    "Database",
    Effect.sync(() => drizzle({ connection: ":memory:" })),
  );
```

## Configuring Databases with Effect

In Brick-TS, database handles are managed through the `database<Self>()` helper from `@brickkit/crud`. It defines a typed `Context.Service` and a corresponding `Layer`.

### 1. SQLite Configuration

For local development, integration tests, or edge deployments with LibSQL or Bun SQLite:

```ts title="src/db/sqlite.ts"
import { database } from "@brickkit/crud";
import { drizzle } from "drizzle-orm/libsql";
import { Effect } from "effect";

export interface SqliteDb {}
export const { Service: SqliteDb, layer: SqliteLive } = database<SqliteDb>()(
  "SqliteDb",
  Effect.sync(() => {
    const url = process.env.DATABASE_URL ?? "file:local.db";
    return drizzle({ connection: url });
  }),
);
```

Use `sqliteStore(table, SqliteDb)` when implementing CRUD contracts.

### 2. PostgreSQL Configuration

For production PostgreSQL workloads using connection pooling (via `pg`, `postgres.js`, or Neon):

```ts title="src/db/postgres.ts"
import { database } from "@brickkit/crud";
import { drizzle } from "drizzle-orm/node-postgres";
import { Effect } from "effect";
import pg from "pg";

export interface PostgresDb {}
export const { Service: PostgresDb, layer: PostgresLive } =
  database<PostgresDb>()(
    "PostgresDb",
    Effect.acquireRelease(
      Effect.sync(() => {
        const pool = new pg.Pool({
          connectionString: process.env.DATABASE_URL,
          max: 20,
        });
        return drizzle({ client: pool });
      }),
      (db) =>
        Effect.promise(async () => {
          // Drains pool connections when app.dispose() is called
          await (db as any).$client?.end();
        }),
    ),
  );
```

Use `postgresStore(table, PostgresDb)` when implementing CRUD contracts.

## Scoped Resource Lifetime

When your application starts, `Brick.app` builds the database layer inside a dedicated `Scope`. When `await app.dispose()` runs:

1. Pending requests are aborted.
2. In-flight database transactions are finished or canceled.
3. The database release finalizer executes, closing connection pools and freeing file handles.

This eliminates connection leaks during test runs and ensures zero-downtime rolling deploys.

## Migrations with Drizzle Kit

Brick uses standard Drizzle migrations. Manage migrations with `drizzle-kit`:

### 1. Drizzle Config

Create `drizzle.config.ts`:

```ts title="drizzle.config.ts"
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  schema: "./src/**/schema.ts",
  out: "./drizzle",
  dialect: "postgresql",
  dbCredentials: {
    url: process.env.DATABASE_URL!,
  },
});
```

### 2. Generate and Apply Migrations

```bash
# Generate SQL migration files from Drizzle schema definitions
bunx drizzle-kit generate

# Apply migrations to the database
bunx drizzle-kit migrate
```

You can also run migrations via the Brick CLI:

```bash
bunx brick migrate
```
