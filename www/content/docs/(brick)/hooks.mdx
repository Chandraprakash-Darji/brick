---
title: Lifecycle Hooks
description: Intercept CRUD operations before and after writes to validate, transform, and log data.
---

Lifecycle hooks allow you to intercept CRUD operations before and after database mutations to normalize payloads, validate business logic, or trigger side effects.

## Minimal Example

Configure hooks on a CRUD resource to normalize inputs before saving and perform side effects after saving:

```ts title="src/services/articles.ts"
import { crudContract, sqliteStore, InvalidInput } from "@brickkit/crud";
import { sqliteTable, text } from "drizzle-orm/sqlite-core";
import { Effect } from "effect";
import { BlogDb } from "./db";

export const articles = sqliteTable("articles", {
  id: text("id").primaryKey(),
  title: text("title").notNull(),
  slug: text("slug").notNull(),
  updatedAt: text("updated_at").notNull(),
});

export const articleContract = crudContract({
  name: "article",
  path: "/api/article",
  table: articles,
  id: "id",
  errors: [],
  fields: {
    id: { read: true },
    title: { read: true, create: true, update: true },
    slug: { read: true },
    updatedAt: { read: true },
  },
});

export const articleActions = articleContract.implement({
  store: sqliteStore(articles, BlogDb),
  access: "public",
  hooks: {
    beforeCreate: ({ data }) =>
      Effect.gen(function* () {
        const title = String(data.title ?? "").trim();
        if (!title) {
          return yield* Effect.fail(
            new InvalidInput({ message: "Article title cannot be blank" }),
          );
        }

        const now = new Date().toISOString();
        return {
          ...data,
          id: crypto.randomUUID(),
          title,
          slug: title.toLowerCase().replace(/\s+/g, "-"),
          updatedAt: now,
        };
      }),

    afterCreate: ({ row }) =>
      Effect.sync(() => {
        console.log(`Article created: ${row.id} (${row.title})`);
      }),

    beforeUpdate: ({ data }) =>
      Effect.succeed({
        ...data,
        updatedAt: new Date().toISOString(),
      }),
  },
});
```

## Available Lifecycle Hooks

Hooks are configured inside `contract.implement({ hooks })`:

| Hook           | Parameter      | Return Type                          | Description                                                               |
| :------------- | :------------- | :----------------------------------- | :------------------------------------------------------------------------ |
| `beforeCreate` | `{ data }`     | `Effect<Partial<InsertModel>, E, R>` | Normalizes or enriches creation payload before inserting to the database. |
| `afterCreate`  | `{ row }`      | `Effect<void, E, R>`                 | Runs side effects after a row is successfully inserted.                   |
| `beforeUpdate` | `{ data, id }` | `Effect<Partial<InsertModel>, E, R>` | Normalizes update data before modifying the existing row.                 |
| `afterUpdate`  | `{ row }`      | `Effect<void, E, R>`                 | Runs side effects after a row has been updated.                           |
| `beforeDelete` | `{ id }`       | `Effect<void, E, R>`                 | Guard or clean up references before row deletion.                         |
| `afterDelete`  | `{ id }`       | `Effect<void, E, R>`                 | Runs side effects after row deletion completes.                           |

## Immutable Data Transformation

In Brick-TS, `beforeCreate` and `beforeUpdate` hooks return transformed data objects immutably. Unlike legacy frameworks that mutate objects in place, you return a new object:

```ts
beforeCreate: ({ data }) =>
  Effect.succeed({
    ...data,
    id: crypto.randomUUID(),
    createdAt: new Date().toISOString(),
  }),
```

This ensures hooks can set fields that clients are not permitted to provide via the API (such as `id`, `authorId`, or generated timestamps).

## Validating in Hooks

Hooks execute within the Effect pipeline. To reject an operation, fail with an error:

```ts
beforeCreate: ({ data }) =>
  Effect.gen(function* () {
    if (data.title && data.title.length < 3) {
      return yield* Effect.fail(
        new InvalidInput({ message: "Title must be at least 3 characters" }),
      );
    }
    return data;
  }),
```

When a hook fails, database operations are aborted, no records are written, and the error response is returned to the client.

## Scrubbers (`scrub`)

For sensitive fields (such as password hashes, email addresses, or internal metadata), use scrubbers to sanitize data before sending to clients:

```ts
export const userActions = userContract.implement({
  store: sqliteStore(usersTable, UserDb),
  access: "public",
  scrub: {
    read: (row) =>
      Effect.succeed({
        ...row,
        email: maskEmail(row.email),
      }),
  },
});
```

## Transaction Safety

In `@brickkit/crud`, store operations run inside database transactions where supported. If a `beforeCreate` hook or database constraint fails, the entire transaction rolls back automatically.
