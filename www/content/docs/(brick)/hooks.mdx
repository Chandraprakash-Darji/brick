---
title: CRUD hooks
description: Separate write normalization from response scrubbing
---

Configure `hooks` inside `crud()` options. Before hooks can normalize data or
assign trusted internal columns; after hooks observe completed writes. Available
hooks are before/after create, update, and delete. Hook parameters include context
and error helpers; update/delete hooks also receive the target identifier and
existing row. After-create/update receive the persisted result.

```ts
crud({
  fields: { title: { read: true, create: true, update: true } },
  hooks: {
    beforeCreate: ({ data, error }) => {
      data.title = String(data.title).trim();
      if (!data.title) error.BAD_REQUEST("Title cannot be blank");
    },
  },
});
```

`crud` is imported from `@brickkit/crud`. Hook data is a record of trusted table
values; hooks must use real column keys. Assign explicit timestamps or owners
here, or use database defaults. There is no implicit timestamp detection.
Hooks cannot return hidden fields to consumers. Response `scrub` policies run
separately after querying and do not change persisted data. After hooks run after
the write and cannot undo it; use application transactions for atomic side effects.
