---
title: Resources and CRUD
description: Declare a table host and install CRUD with explicit field policies
---

Core resources declare identity and a table. They register no actions. Install
`crud()` from `@brickkit/crud` to add operations and HTTP routes.

```ts
import {
  defineDatabase,
  defineService,
  sqliteTable,
  text,
} from "@brickkit/core";
import { crud } from "@brickkit/crud";

const pages = sqliteTable("pages", {
  id: text("id")
    .primaryKey()
    .$defaultFn(() => crypto.randomUUID()),
  title: text("title").notNull(),
  email: text("email"),
  internalNotes: text("internal_notes"),
});
const database = defineDatabase({ tables: { pages } });
const service = defineService("pages", { database });
const page = service.resource({ name: "page", table: pages, id: pages.id }).use(
  crud({
    fields: {
      id: { read: true, filter: ["eq", "in"] },
      title: {
        read: true,
        create: true,
        update: true,
        filter: ["eq", "contains"],
        sort: true,
      },
      email: {
        read: true,
        create: true,
        update: true,
        scrub: ({ value }) =>
          value === null ? null : value.replace(/^(.).*(@.*)$/, "$1***$2"),
      },
    },
  }),
);
```

The application owns schema creation and migrations. Neither declaration nor
plugin installation creates tables. Unlisted fields and omitted permissions are
disabled. `read`, `create`, `update`, allowed `filter` operators, and `sort` are
independent. `schema` overrides validation for a field. `scrub` changes returned
values, including local calls and write results, without changing stored values.
Scrubbers must handle nullable values. Filtering a masked field requires an
explicit filter permission.

```ts
await page.list({
  input: {
    select: ["id", "title"],
    where: { field: "title", op: "contains", value: "Hello" },
    orderBy: [{ field: "title", direction: "asc" }],
    limit: 20,
    offset: 0,
    includeTotal: true,
  },
});
await page.update({ input: { id: "page-1", data: { title: "Updated" } } });
```

List returns `{ items, limit, offset, total? }`. Totals execute only when requested.
`where` supports nested `and` and `or` arrays. Operators must be enabled for the
field and compatible with the column type. Unknown projections, writes, filters
and ordering fail validation. Local list/findOne projections infer selected keys;
serialized browser contracts describe projected rows with optional properties.

Local vs HTTP row precision: local `list`/`get` actions are typed
`Selected<T, F, S>` — the `select` projection narrows the return type. Over
HTTP every readable key is optional in the row schema because `select`
projections omit keys, so validate presence client-side when using `select`.

| Method | Path                 | Action  |
| ------ | -------------------- | ------- |
| POST   | `/api/page/query`    | list    |
| GET    | `/api/page/:id`      | get     |
| POST   | `/api/page`          | create  |
| PATCH  | `/api/page/:id`      | update  |
| DELETE | `/api/page/:id`      | delete  |
| POST   | `/api/page/find-one` | findOne |
| POST   | `/api/page/count`    | count   |
| POST   | `/api/page/exists`   | exists  |

`get` returns NOT_FOUND for a missing key; `findOne` returns null. Count returns
`{count}` and exists returns `{exists}`. The configured app prefix replaces `/api`.
There is no GET list or PUT replacement route.

Use `operations: false` or `operations: {delete:false}` to remove capabilities.
Use `routes: false` or `routes: {list:false}` to retain local actions without HTTP,
OpenAPI, or generated browser exposure. Named route overrides accept `path` and
`scope`, for example `routes: {count:{path:"/page-count",scope:"app"}}`. App scope
still respects the app prefix. See [plugins](/docs/plugins/build-plugin).

CRUD also accepts `defaultLimit`, `maxLimit`, `access`, and lifecycle `hooks`.
No field-name conventions generate IDs, timestamps, owner values or projections.
Use database defaults or explicit trusted hooks.
