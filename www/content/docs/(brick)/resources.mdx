Resources link Drizzle database tables to services, while the `@brickkit/crud` package provides type-safe, deny-by-default data operations.

## Minimal Example

Attach a declarative CRUD contract to a Drizzle table with explicit field policies and public access:

```ts title="src/services/pages.ts"
import { Brick } from "@brickkit/core";
import { crudContract, sqliteStore } from "@brickkit/crud";
import { sqliteTable, text } from "drizzle-orm/sqlite-core";
import { PagesDb } from "./db";

// 1. Declare the database table with Drizzle
export const pages = sqliteTable("pages", {
  id: text("id")
    .primaryKey()
    .$defaultFn(() => crypto.randomUUID()),
  title: text("title").notNull(),
  content: text("content"),
  internalNotes: text("internal_notes"),
});

// 2. Define the CRUD contract with field policies
export const pageContract = crudContract({
  name: "page",
  path: "/api/page",
  table: pages,
  id: "id",
  errors: [],
  fields: {
    id: { read: true, filter: ["eq", "in"] },
    title: {
      read: true,
      create: true,
      update: true,
      filter: ["eq", "contains"],
      sort: true,
    },
    content: { read: true, create: true, update: true },
    // internalNotes is omitted: completely hidden from reads, writes, and filters
  },
});

// 3. Implement the contract with a database store and access policy
export const pageActions = pageContract.implement({
  store: sqliteStore(pages, PagesDb),
  access: "public",
});

// 4. Register the CRUD actions on the service
export const pagesService = Brick.service("pages", {
  actions: pageActions,
});
```

### Schema

Brick does not generate owner or timestamp columns automatically. Declare them in your table and populate them with Drizzle defaults or CRUD hooks when needed.

These columns match the Drizzle tables in the example. Defaults marked as application defaults run in Drizzle, rather than in SQL.

export const pagesSchemaFields = [
  {
    name: "id",
    type: "text",
    description: "Row identifier.",
    isPrimaryKey: true,
    defaultValue: "crypto.randomUUID() (application)",
  },
  {
    name: "title",
    type: "text",
    description: "Display title.",
  },
  {
    name: "content",
    type: "text",
    description: "Page content.",
    isOptional: true,
  },
  {
    name: "internal_notes",
    type: "text",
    description: "Internal notes, hidden by the CRUD field policy.",

  },

<Callout type="warn">
  **CRUD is Deny-by-Default**: `access` is a required option. `access: "public"` allows every call. `access: { authorize, scope }` runs your `authorize` check on every operation and adds your `scope` condition to SQL queries. An access object without `authorize` rejects every call with `Forbidden` (HTTP 403).
</Callout>

## Generated Operations

When `crudContract` is implemented, it produces a dictionary of typed action implementations:

| Operation | Action Name    | Route                     | Description                                                               |
| :-------- | :------------- | :------------------------ | :------------------------------------------------------------------------ |
| `list`    | `page.list`    | `POST /api/page/query`    | Query rows with filtering, pagination (`limit`/`offset`), and sorting.    |
| `findOne` | `page.findOne` | `POST /api/page/find-one` | Query for a single row matching criteria. Returns `null` if not found.    |
| `get`     | `page.get`     | `GET /api/page/:id`       | Fetch a single row by primary key. Fails with `NotFound` (404) if absent. |
| `create`  | `page.create`  | `POST /api/page`          | Insert a new row using fields marked with `create: true`.                 |
| `update`  | `page.update`  | `PATCH /api/page/:id`     | Update an existing row by ID using fields marked with `update: true`.     |
| `delete`  | `page.delete`  | `DELETE /api/page/:id`    | Delete a row by primary key. Returns `{ success: true }`.                 |
| `count`   | `page.count`   | `POST /api/page/count`    | Count total rows matching a filter condition.                             |
| `exists`  | `page.exists`  | `POST /api/page/exists`   | Check whether any row matches a filter condition. Returns a boolean.      |

## Field Policies (`fields`)

The `fields` option governs column-level read, write, filter, and sort permissions:

| Policy Property | Type               | Default | Description                                                               |
| :-------------- | :----------------- | :------ | :------------------------------------------------------------------------ |
| `read`          | `boolean`          | `false` | When `true`, column is included in output schemas for `list`, `get`, etc. |
| `create`        | `boolean`          | `false` | When `true`, column is accepted in the input schema for `create`.         |
| `update`        | `boolean`          | `false` | When `true`, column is accepted in the input schema for `update`.         |
| `filter`        | `FilterOperator[]` | `false` | Array of allowed filter operators when querying via `list`, `count`, etc. |
| `sort`          | `boolean`          | `false` | When `true`, column can be specified in `orderBy` clauses.                |

### Allowed Filter Operators

The following operators can be enabled in `filter`:

- Equality: `"eq"`, `"ne"`
- Comparison: `"gt"`, `"gte"`, `"lt"`, `"lte"`
- Sets: `"in"`, `"notIn"` (enforces array length between 1 and 1000)
- Ranges: `"between"` (expects a 2-element tuple `[min, max]`)
- Nullability: `"isNull"`, `"isNotNull"`
- String search: `"contains"`

## Querying Resources (`page.list`)

The `list` operation accepts a type-safe JSON query payload:

```bash
curl -X POST http://localhost:4000/api/page/query \
  -H "Content-Type: application/json" \
  -d '{
    "where": {
      "and": [
        { "field": "title", "op": "contains", "value": "Release" },
        { "field": "id", "op": "in", "value": ["pg_1", "pg_2"] }
      ]
    },
    "orderBy": [
      { "field": "title", "direction": "asc" }
    ],
    "limit": 20,
    "offset": 0,
    "includeTotal": true
  }'
```

Response:

```json
{
  "items": [{ "id": "pg_1", "title": "Release 1.0", "content": "..." }],
  "total": 1,
  "limit": 20,
  "offset": 0
}
```

### Fetch a Single Row (`page.get`)

```bash
curl http://localhost:4000/api/page/pg_1
```

### Create a Row (`page.create`)

```bash
curl -X POST http://localhost:4000/api/page \
  -H "Content-Type: application/json" \
  -d '{"title": "New Page", "content": "Hello World"}'
```

### Update a Row (`page.update`)

```bash
curl -X PATCH http://localhost:4000/api/page/pg_1 \
  -H "Content-Type: application/json" \
  -d '{"title": "Updated Title"}'
```

### Delete a Row (`page.delete`)

```bash
curl -X DELETE http://localhost:4000/api/page/pg_1
```

## Disabling Specific Operations

You can disable operations by setting them to `false` in `crudContract({ operations })`:

```ts title="src/services/readonly-pages.ts"
export const readOnlyPageContract = crudContract({
  name: "page",
  path: "/api/page",
  table: pages,
  id: "id",
  errors: [],
  fields: {
    id: { read: true },
    title: { read: true },
  },
  operations: {
    create: false,
    update: false,
    delete: false,
  },
});
```

Only `list`, `findOne`, `get`, `count`, and `exists` will be generated. The mutation endpoints will not exist on the router.

## Supported Database Stores

`@brickkit/crud` provides first-class stores for SQLite and PostgreSQL:

```ts
import { sqliteStore, postgresStore } from "@brickkit/crud";

// SQLite (via Bun native SQLite or LibSQL)
const sqliteActions = pageContract.implement({
  store: sqliteStore(pages, SqliteDb),
  access: "public",
});

// PostgreSQL (via node-postgres or Neon)
const pgActions = pageContract.implement({
  store: postgresStore(pages, PgDb),
  access: "public",
});
```
