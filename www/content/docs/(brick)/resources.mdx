Resources are the core of a Brick-TS app. Each resource maps a Drizzle table to full CRUD actions, REST routes, owner scoping, hooks, and OpenAPI entries.

## Declaration

```ts
import {
  defineService,
  defineDatabase,
  sqliteTable,
  text,
  integer,
  eq,
  t,
} from "@brickkit/core";

export const pagesTable = sqliteTable("pages", {
  id: text("id").primaryKey(),
  slug: text("slug").notNull().unique(),
  title: text("title").notNull(),
  content: text("content").notNull(),
  contentType: text("content_type")
    .$type<"markdown" | "html">()
    .notNull()
    .default("markdown"),
  isPublic: integer("is_public", { mode: "boolean" }).notNull().default(false),
  userId: text("user_id"),
  createdAt: text("created_at").notNull(),
  updatedAt: text("updated_at").notNull(),
});

export const pagesDb = defineDatabase({
  path: "./data/pages.db",
  tables: { pagesTable },
});

export const pagesService = defineService("pages", { database: pagesDb });

export const pagesResource = pagesService.resource({
  name: "page",
  table: pagesTable,
  ownerField: "userId",
  operations: {
    list: { defaultLimit: 20, maxLimit: 100 },
    get: true,
    create: true,
    update: true,
    delete: true,
  },
  hooks: {
    beforeCreate: async ({ data, ctx, error }) => {
      const exists = await ctx.db
        .select()
        .from(pagesTable)
        .where(eq(pagesTable.slug, data.slug));
      if (exists.length > 0) {
        error.CONFLICT(`Slug '${data.slug}' is already taken`);
      }
    },
  },
});

// CRUD actions generated automatically by the resource
export const {
  create: createPage,
  get: getPage,
  list: listPages,
  update: updatePage,
  delete: deletePage,
} = pagesResource.actions;
```

## Config reference

| Option                                    | Meaning                                                                                                                        |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `name`                                    | Singular resource name; drives action names (`page.create`), REST paths (`/api/page`), and the plural (`pages`)                |
| `table`                                   | Drizzle table (`sqliteTable` / `pgTable`). Its columns derive the row, create, update, get, delete, and list schemas           |
| `ownerField`                              | Drizzle-key column holding the owner's user id. Enables owner scoping on list and ownership checks on get/update/delete        |
| `idField`                                 | PK column key (default `"id"`)                                                                                                 |
| `idPrefix` / `idGenerator`                | ID minting for creates (default `pg_<rand>` for a `page` resource) — see [Primary Keys](/docs/primary-keys)                    |
| `pluralName`                              | Override the derived plural used in list responses                                                                             |
| `operations`                              | `list` (`{ defaultLimit, maxLimit, searchable, sortable, defaultSort }` or boolean), `get`/`create`/`update`/`delete` booleans |
| `hooks`                                   | `beforeCreate`, `afterCreate`, `beforeUpdate`, `afterUpdate`, `beforeDelete`, `afterDelete` — see [Hooks](/docs/hooks)         |
| `fields`                                  | Per-column TypeBox overrides keyed by Drizzle key or DB column name                                                            |
| `searchable` / `sortable` / `defaultSort` | Search and sort behavior for list — see [Resource Lifecycle](/docs/resource-lifecycle)                                         |
| `excludeFromList`                         | Columns excluded from the default list projection (default `["content"]`)                                                      |
| `errors`                                  | Extra named error definitions merged into every CRUD action                                                                    |

## What you get

Each enabled operation registers an action on the service (`page.create`, `page.get`, `page.list`, `page.update`, `page.delete`, plus camelCase aliases like `createPage`) and REST routes via `brick`:

- `GET /api/page` → `page.list`
- `POST /api/page` → `page.create`
- `GET /api/page/:id` → `page.get`
- `PATCH` / `PUT /api/page/:id` → `page.update`
- `DELETE /api/page/:id` → `page.delete`

Create input excludes the PK, owner, and timestamp columns (they are auto-populated). Update input requires the id and treats every other editable field as optional. The create/update/get/delete inputs and the full row output are TypeBox schemas derived from the table — override individual columns with `fields` when you need stricter validation (e.g. a slug pattern).
