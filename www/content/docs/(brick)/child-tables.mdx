---
title: Related tables
description: Use explicit tables and target mappings
---

Relations are application or resource-plugin concerns. Declare comment storage
explicitly and keep its field policies in `comments({table,columns,fields})`.
The parent table and identifier come from the resource plugin's setup context.

```ts
const page = service
  .resource({ name: "page", table: pagesTable, id: pagesTable.id })
  .use(
    comments({
      table: pageCommentsTable,
      columns: {
        targetId: pageCommentsTable.pageId,
        body: pageCommentsTable.body,
      },
      fields: { body: { read: true, create: true, update: true } },
    }),
  );
```

This illustrates an application-defined comments factory, not a published Brick
comments package. Install independently on posts with a post comment table.
Validate target existence and authorization in that plugin. Database foreign
keys enforce relationships when configured by the application. Core never adds
columns, foreign keys, or tables during installation.
