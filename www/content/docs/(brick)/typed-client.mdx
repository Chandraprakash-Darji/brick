Brick-TS provides end-to-end typed client SDKs that share Effect Schema contracts between backend services and frontend browser applications without leaking server dependencies.

## Minimal Example

Define a browser-safe contract module in `src/contract.ts` using `action` from `@brickkit/core/contracts` and native `HttpApi` and `HttpApiGroup` values. This module contains only schemas and has zero database or server imports:

```ts title="src/contract.ts"
import { action, NotFound } from "@brickkit/core/contracts";
import { Schema } from "effect";
import { HttpApi, HttpApiGroup } from "effect/http-api";

export const GetUser = action("getUser", "/api/users/getUser", {
  input: Schema.Struct({ id: Schema.String }),
  output: Schema.Struct({ id: Schema.String, name: Schema.String }),
  errors: [NotFound],
});
export const Api = HttpApi.make("brick").add(
  HttpApiGroup.make("users").add(GetUser.endpoint),
);
```

Consume the contract in your frontend or node client using `createClient` from `@brickkit/client`:

```ts title="src/client.ts"
import { createClient } from "@brickkit/client";
import { Api } from "./contract";

// Synchronous creation with background initialization
const { client, ready, dispose } = createClient(Api, {
  baseUrl: "http://localhost:4000",
  fetchOptions: { credentials: "include" },
});

try {
  // Methods are fully typed from the contract schema:
  const user = await client.users.getUser({ payload: { id: "usr_42" } });
  console.log("User found:", user.name);
} finally {
  await dispose();
}
```

<Callout type="info">
  `createClient` is synchronous and returns `{ client, ready, dispose }`. The underlying client runtime initializes in the background. Calls made on `client` await initialization automatically, or you can explicitly await `ready`.
</Callout>

## Complete Browser/Server Bundle Isolation

Direct TypeScript type imports from server files (common in basic RPC frameworks) risk leaking server-only dependencies into frontend bundles:

- Node.js native modules (`node:fs`, `node:crypto`)
- Database drivers (`pg`, `drizzle-orm`, `@libsql/client`)
- Server environment variables and secrets

Brick avoids this by structuring applications into two layers:

1. **Contract Modules** (`src/contract.ts`): Pure Effect Schema definitions, error classes, and `HttpApi` groups. Completely browser-safe with zero server dependencies.
2. **Implementation Modules** (`src/services/...`): Server handlers, database queries, and layers that implement the contracts.

Frontend applications import only the contract module or the file generated by `brick gen client`.

## Promise Client vs Effect Client

`@brickkit/client` provides two client constructors:

### 1. Promise Client (`createClient`)

Designed for standard frontend frameworks (React, Vue, Svelte, Next.js, Vite). Method calls accept `{ payload, query, params, headers }` and return standard JavaScript `Promise` values:

```ts
const { client, dispose } = createClient(Api, {
  baseUrl: "http://localhost:4000",
});

const user = await client.users.getUser({ payload: { id: "usr_42" } });

// For CRUD endpoints, request parts map to params or payload:
// Path params (GET /:id, DELETE /:id):
// const page = await client.pages["page.get"]({ params: { id: "pg_1" } });
// await client.pages["page.delete"]({ params: { id: "pg_1" } });

// JSON payload (POST /query, POST /):
// const items = await client.pages["page.list"]({ payload: { limit: 10 } });
// const created = await client.pages["page.create"]({ payload: { title: "New Page" } });

// Mixed params and payload (PATCH /:id):
// const updated = await client.pages["page.update"]({
//   params: { id: "pg_1" },
//   payload: { title: "Updated Title" },
// });
```

Calls from pre-Effect frontends keep working: flat arguments are split into request parts automatically (`:id` segments become `params`, the rest becomes the payload), so `client.pages["page.create"]({ title: "New Page" })` and `client.pages["page.get"]({ id: "pg_1" })` behave like the `{ payload }` / `{ params }` forms above. New code should prefer the explicit request-parts form.

### 2. Native Effect Client (`createEffectClient`)

For Effect-native consumers, `createEffectClient` is an alias for `HttpApiClient.make`. It preserves typed failures in the Effect error channel (`E`) and service requirements in `R`:

```ts
import { createEffectClient } from "@brickkit/client";
import { Effect } from "effect";
import { Api } from "./contract";

const program = Effect.gen(function* () {
  const client = yield* createEffectClient(Api, {
    baseUrl: "http://localhost:4000",
  });
  const user = yield* client.users.getUser({ payload: { id: "usr_42" } });
  return user;
});
```

## Client Configuration Options

`createClient` accepts the following options:

| Option            | Type                                 | Description                                                                         |
| :---------------- | :----------------------------------- | :---------------------------------------------------------------------------------- |
| `baseUrl`         | `string \| URL`                      | Base URL of the running Brick API server.                                           |
| `fetchOptions`    | `RequestInit`                        | Standard web `RequestInit` options (e.g. `credentials: "include"`, custom headers). |
| `transformClient` | `(client: HttpClient) => HttpClient` | Hook to intercept or wrap outgoing HTTP requests.                                   |
| `layer`           | `Layer<ClientServices, E, never>`    | Effect Layer providing client-side middleware or services if required by schemas.   |

## Automated Contract Synchronization (`brick gen client`)

To generate a verified client re-export, configure `client` in `Brick.app`:

```ts title="src/app.ts"
export default Brick.app({
  services: [usersService],
  layer: AppLive,
  client: {
    module: "./contract",
    exportName: "Api",
  },
});
```

Then run the generator CLI:

```bash
bunx brick gen client src/app.ts --output src/generated-contract.ts
```

The generator inspects your application's routes and schemas, compares them with `src/contract.ts`, and verifies that the browser contract is an exact match for the production server. If routes drift or schemas mismatch, the command fails immediately.
