title: Typed Client SDK
description: Call backend actions with full end-to-end type safety in frontend applications without build-time codegen.
---

The Brick-TS client SDK provides end-to-end typed HTTP communication between frontend applications and backend services without code generation.

## Minimal Example

The client is typed by a generated contract: browser-safe route metadata and transport types derived from your app. Your app entry must default-export a `BrickApp` created by `brick()` (without calling `.listen()`).

Generate the contract with the Vite plugin, which writes `_brick/contract.ts` on dev startup and build and regenerates it when the app changes:

```ts title="vite.config.ts"
import { defineConfig } from "vite";
import { brickClient } from "@brickkit/cli/vite";

export default defineConfig({
  plugins: [brickClient({ entry: "./src/api/app.ts" })],
});
```

Or generate it without Vite:

```bash
brick gen client src/api/app.ts
# default output: _brick/contract.ts
brick gen client src/api/app.ts --output frontend/src/contract.ts
```

Then import `createBrickClient` from `@brickkit/core/client` (a browser-safe subpath) and pass the contract:

```ts title="src/lib/api.ts"
import { createBrickClient } from "@brickkit/core/client";
import { contract } from "../../_brick/contract";

export const api = createBrickClient({
  baseUrl: "http://localhost:4000",
  contract,
});

// CRUD resources live at the root: api.<resource>.<operation>
const response = await api.page.list({
  where: { field: "title", op: "contains", value: "Launch" },
  limit: 5,
});

console.log(response.items); // Typed from the resource's read fields
```

Custom actions are grouped by service name (`api.<service>.<action>`), and dotted action names become nested namespaces. The contract carries each action's HTTP method and path, including CRUD routes and custom `path`/`method` overrides. GET and DELETE input is sent as a query string; other methods send JSON.

## Client Configuration (`createBrickClient`)

The client constructor accepts the following options:

| Option      | Type                                                                                          | Default            | Description                                                                                                                     |
| :---------- | :-------------------------------------------------------------------------------------------- | :----------------- | :------------------------------------------------------------------------------------------------------------------------------ |
| `baseUrl`   | `string`                                                                                      | _(Required)_       | Server origin (e.g. `"http://localhost:4000"`). Trailing slashes are trimmed.                                                   |
| `contract`  | `Record<string, any>`                                                                         | `undefined`        | Generated contract. Without it, every call is `POST {prefix}/<service>/<action>`, so CRUD and custom-path routes won't resolve. |
| `prefix`    | `string`                                                                                      | `"/api"`           | Route prefix used only for calls without contract metadata. Must match `brick({ prefix })`.                                     |
| `headers`   | `Record<string, string> \| (() => Record<string, string> \| Promise<Record<string, string>>)` | `undefined`        | Static headers, or a function re-evaluated on every call.                                                                       |
| `fetch`     | `(input, init) => Promise<Response>`                                                          | `globalThis.fetch` | Custom fetch implementation for tests, proxies, or `credentials: "include"`.                                                    |
| `timeoutMs` | `number`                                                                                      | `undefined`        | Default per-call timeout in milliseconds (uses `AbortSignal.timeout`).                                                          |
| `signal`    | `AbortSignal`                                                                                 | `undefined`        | Default abort signal for every call.                                                                                            |

### Dynamic Authentication Headers

Pass an async function to `headers` to attach dynamic authentication tokens to every outgoing request:

```ts title="src/lib/api.ts"
export const api = createBrickClient({
  baseUrl: "https://api.example.com",
  contract,
  headers: async (): Promise<Record<string, string>> => {
    const token = await getSessionToken();
    return token ? { Authorization: `Bearer ${token}` } : {};
  },
});
```

## Per-Call Options

Every client invocation accepts an optional second argument for request-specific headers, an abort signal, or a timeout. Per-call headers merge over the client defaults:

```ts title="src/components/PageList.tsx"
const controller = new AbortController();

const pages = await api.page.list(
  { limit: 10 },
  {
    signal: controller.signal,
    headers: { "X-Custom-Trace": "req_123" },
  },
);
```

Only one signal is applied per call, in this order: per-call `signal`, then the timeout signal (per-call `timeoutMs`, else the client `timeoutMs`), then the client `signal`. Passing both `signal` and `timeoutMs` on the same call ignores the timeout. Aborts are not wrapped: they reject with the native `AbortError`.

## Error Handling

When a request fails, the client rejects according to the response:

- A body with a string `code` (declared errors, standard helpers, authorization failures) → `ActionExecutionError` with `code`, `status`, `message`, and `details`.
- A body with `name: "ValidationError"` → `ValidationError` with `errors`.
- Any other 5xx → `BrickServerError`; any other non-OK response, a network failure, or an unparsable body → `BrickTransportError`.

`@brickkit/core/client` exports the client builder, the transport classes and
guards, and the type utilities — but not `ActionExecutionError` or
`ValidationError`, which live in the server entry `@brickkit/core`. In browser
code, narrow them by `err.name` instead:

```ts title="src/lib/fetch-user.ts"
import {
  type InferActionFailure,
  isBrickServerError,
  isBrickTransportError,
} from "@brickkit/core/client";
import { api } from "./api";

try {
  const user = await api.users.getUser({ id: "usr_99" });
} catch (err) {
  if (err instanceof Error && err.name === "ActionExecutionError") {
    // Domain error from the action (declared code or e.g. NOT_FOUND, FORBIDDEN)
    const failure = err as InferActionFailure<unknown>;
    console.error(`[${failure.code}] (${failure.status}): ${failure.message}`);
    console.error("Details:", failure.details);
  } else if (err instanceof Error && err.name === "ValidationError") {
    // TypeBox schema validation failure
    console.error("Validation error:", (err as any).errors);
  } else if (isBrickServerError(err)) {
    // 5xx without a Brick error shape
    console.error("Server failure:", err.status, err.message);
  } else if (isBrickTransportError(err)) {
    // Network failure, unparsable body, or unrecognized 4xx
    console.error("Transport failure:", err.status, err.message);
  }
}
```

## Type Utilities

Extract static types directly from actions or client functions:

```ts title="src/types/client.ts"
import type {
  InferActionErrorCodes,
  InferActionInput,
  InferActionOutput,
} from "@brickkit/core/client";
import type { getUser } from "../server/users";

export type GetUserInput = InferActionInput<typeof getUser>;
export type GetUserOutput = InferActionOutput<typeof getUser>;
export type GetUserErrorCodes = InferActionErrorCodes<typeof getUser>;
```
