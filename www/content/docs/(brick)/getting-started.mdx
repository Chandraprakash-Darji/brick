## Prerequisites

- [Bun](https://bun.sh/) 1.0+
- No database server needed for local dev (SQLite is Bun-native, `:memory:` by default)

## Install

```bash
bun add @brickkit/core @brickkit/cli
```

## Define the table, database, service, and resource

The following minimal SQLite example introduces the API. For a full Postgres app
using the local framework and typed SDK, see `examples/pages` and run
`bun run pages:dev` from the repository root.

```ts
// src/services/pages/service.ts
import {
  defineService,
  defineDatabase,
  sqliteTable,
  text,
  integer,
  eq,
  t,
} from "@brickkit/core";

// 1. Pure Drizzle table — the single source of truth
export const pagesTable = sqliteTable("pages", {
  id: text("id").primaryKey(),
  slug: text("slug").notNull().unique(),
  title: text("title").notNull(),
  content: text("content").notNull(),
  userId: text("user_id"),
  createdAt: text("created_at").notNull(),
  updatedAt: text("updated_at").notNull(),
});

// 2. SQLite database (Bun-only). Omit path for :memory:.
export const pagesDb = defineDatabase({
  path: "./data/pages.db",
  tables: { pagesTable },
});

// 3. Service + resource (automatic CRUD + schema registration)
export const pagesService = defineService("pages", { database: pagesDb });

export const pagesResource = pagesService.resource({
  name: "page",
  table: pagesTable,
  ownerField: "userId",
  operations: {
    list: { defaultLimit: 20, maxLimit: 100 },
    get: true,
    create: true,
    update: true,
    delete: true,
  },
  hooks: {
    beforeCreate: async ({ data, ctx, error }) => {
      const exists = await ctx.db
        .select()
        .from(pagesTable)
        .where(eq(pagesTable.slug, data.slug));
      if (exists.length > 0) {
        error.CONFLICT(`Slug '${data.slug}' is already taken`);
      }
    },
  },
});
```

## Serve it

Export the app separately from the listener so Vite can read its definitions:

```ts
// src/app.ts
import { brick } from "@brickkit/cli";
import { pagesService } from "./services/pages/service";

export default brick({ services: [pagesService] });
```

```ts
// src/index.ts
import app from "./app";

app.listen(4000);
console.log("Brick-TS on http://localhost:4000");
```

```bash
bun run src/index.ts
```

## Verify

| URL                                     | What                                  |
| --------------------------------------- | ------------------------------------- |
| `http://localhost:4000/_health`         | `{ status: "ok", uptime, timestamp }` |
| `http://localhost:4000/_brick/services` | Live architecture introspection       |
| `http://localhost:4000/openapi.json`    | Generated OpenAPI 3.1 spec            |
| `http://localhost:4000/docs`            | Scalar API reference                  |
| `http://localhost:4000/swagger`         | Swagger UI                            |
| `GET http://localhost:4000/api/page`    | List pages                            |
| `POST http://localhost:4000/api/page`   | Create a page                         |

## Call it from a typed frontend

In your Vite frontend, add the Brick plugin before your framework plugins:

```bash
bun add --dev vite@^8
```

```ts
// vite.config.ts
import { defineConfig } from "vite";
import { brickClient } from "@brickkit/cli/vite";

export default defineConfig({
  plugins: [brickClient({ entry: "./src/app.ts" })],
});
```

Run Vite with Bun for this SQLite example:

```bash
bunx --bun vite
```

The plugin generates `_brick/contract.ts` from the default-exported app before
the frontend loads and before production builds, and regenerates it on backend
edits. Add `_brick/` to `.gitignore`. Import the generated contract for
autocomplete and compile-time payload checking:

```ts
// src/client.ts
import { createBrickClient } from "@brickkit/core/client";
import { contract } from "../_brick/contract";

const api = createBrickClient({ baseUrl: "http://localhost:4000", contract });

const pages = await api.page.list({ limit: 10 });
const created = await api.page.create({
  slug: "hello",
  title: "Hello",
  content: "World",
});
```

See [Typed Client](/docs/typed-client) for routing, error handling (`ActionExecutionError` codes, `ValidationError`, transport/server failures, cancellation), auth headers, and timeouts.

Postgres instead of SQLite? Pass `engine: "postgres"` with `tables` and a `url` — see [Schema Management](/docs/migrations). Need a signed-in user on every CRUD op? See [Access Control](/docs/access-control) for the context-resolver + `authorize` pattern.
