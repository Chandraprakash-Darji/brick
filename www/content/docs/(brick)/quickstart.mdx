This guide gets a runnable Effect-native Brick-TS service running locally with Bun and Effect in less than five minutes.

## 1. Install Dependencies

Initialize a new Bun project and install `@brickkit/core`, `@brickkit/cli`, and `effect`:

<Tabs items={["bun", "pnpm", "npm"]}>
  <Tab value="bun">

```bash
mkdir my-brick-app && cd my-brick-app
bun init -y
bun add @brickkit/core @brickkit/cli effect
```

  </Tab>
  <Tab value="pnpm">

```bash
pnpm add @brickkit/core @brickkit/cli effect
```

  </Tab>
  <Tab value="npm">

```bash
npm install @brickkit/core @brickkit/cli effect
```

  </Tab>

## 2. Define the Action and Service

Create `src/users.ts` with an action definition, Effect Schema contracts, a typed error, and a service container:

```ts title="src/users.ts"
import { Brick } from "@brickkit/core";
import { NotFound } from "@brickkit/core/contracts";
import { Effect, Schema } from "effect";

const GetUser = Brick.action("getUser", "/api/users/getUser", {
  input: Schema.Struct({ id: Schema.String }),
  output: Schema.Struct({ id: Schema.String, name: Schema.String }),
  errors: [NotFound],
});
const getUser = GetUser(({ id }) =>
  id === "usr_42"
    ? Effect.succeed({ id, name: "Ada" })
    : Effect.fail(new NotFound({ message: "User not found" })),
);
export const usersService = Brick.service("users", { actions: { getUser } });
```

### Understanding the Action Definition

- `Brick.action(name, path, schemas)`: Defines an action contract. It specifies the unique action name, HTTP route, input and output schemas, and declared error classes.
- Calling `GetUser(handler)`: Attaches the handler function. The handler receives decoded input (`{ id: string }`) and returns an `Effect`.
- `NotFound`: A built-in tagged error schema annotated with HTTP status 404.
- `Brick.service(name, { actions })`: Groups actions into an immutable domain service.

## 3. Export the Application

Create `src/app.ts` to compose the services and export the scoped application:

```ts title="src/app.ts"
import { Brick } from "@brickkit/core";
import { Layer } from "effect";
import { usersService } from "./users";

export default Brick.app({
  services: [usersService],
  layer: Layer.empty,
  docs: { path: "/reference" },
});
```

`Brick.app` takes:

- `services`: An array of immutable services to mount.
- `layer`: An Effect `Layer` supplying dependencies (such as database pools or external clients). For this in-memory service, `Layer.empty` is used.
- `docs`: Automatically mounts interactive Scalar API documentation at `/reference`.

## 4. Start the Server

Run the development server with live reload using the `brick` CLI:

```bash
bunx brick dev src/app.ts --port 4000
```

The CLI loads your entry and prints the registered services and routes:

```text
🧱 Brick-TS Development Server
   Registered Services: 1
   • users (1 action)
     -> POST   /api/users/getUser

⚡ API Gateway running on: http://localhost:4000
📖 Interactive Docs:     http://localhost:4000/reference
```

## 5. Test the API Endpoints

Execute HTTP requests against the generated endpoint. Custom actions accept POST requests with JSON payloads, while CRUD resources map to standard REST endpoints (GET, POST, PATCH, DELETE):

### Successful Request (200 OK)

```bash
curl -X POST http://localhost:4000/api/users/getUser \
  -H "Content-Type: application/json" \
  -d '{"id": "usr_42"}'
```

Response:

```json
{
  "id": "usr_42",
  "name": "Ada"
}
```

### Missing Record (404 Not Found)

When an action fails with a declared `NotFound` tagged error:

```bash
curl -X POST http://localhost:4000/api/users/getUser \
  -H "Content-Type: application/json" \
  -d '{"id": "usr_999"}'
```

Response (HTTP status 404):

```json
{
  "_tag": "NotFound",
  "message": "User not found"
}
```

### Schema Validation Error (400 Bad Request)

If an invalid payload is sent (such as a number instead of a string `id`), Effect Schema validation rejects the request before the handler runs:

```bash
curl -X POST http://localhost:4000/api/users/getUser \
  -H "Content-Type: application/json" \
  -d '{"id": 123}'
```

Response (HTTP status 400):

```json
{
  "message": "Expected string, actual 123"
}
```

## 6. Consume from a Frontend Client

Frontend clients consume endpoints using `@brickkit/client` with zero build steps or manual code generation:

```ts title="src/client.ts"
import { createClient } from "@brickkit/client";
import { Api } from "./contract";

const { client, dispose } = createClient(Api, {
  baseUrl: "http://localhost:4000",
});

try {
  const user = await client.users.getUser({ payload: { id: "usr_42" } });
  console.log("Found user:", user.name);
} finally {
  await dispose();
}
```
