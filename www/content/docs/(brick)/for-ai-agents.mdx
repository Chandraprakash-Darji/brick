Give your coding agent the documentation index, then let it fetch the pages needed for the task.

## Read markdown documentation

- [llms.txt](/llms.txt) lists every documentation page, grouped by section with a short description.
- [llms-full.txt](/llms-full.txt) contains all pages in sidebar order.
- Each page has a markdown URL, such as [quickstart.md](/docs/quickstart.md).

To request markdown at the regular page URL:

```bash
curl -H 'Accept: text/markdown' https://brick.rega.run/docs/quickstart
```

Start an agent task with this instruction:

```text
Read https://brick.rega.run/llms.txt. Fetch the relevant markdown pages before
changing this Brick project. Check package.json for the installed Brick version
and follow the existing Effect-native service definitions, contracts, and verification scripts.
```

In Cursor, add the index URL as documentation context or include it in your chat prompt. In Claude Code, put the instruction in your project's `CLAUDE.md`. In Copilot, put it in `.github/copilot-instructions.md`. If your agent cannot fetch URLs, download the required `.md` files and add them to its context.

## Add project instructions

Copy this into your project's `AGENTS.md`, or adapt it for your agent's instruction file:

```md
## Brick

- Read https://brick.rega.run/llms.txt and fetch relevant markdown pages.
- Check the installed @brickkit package versions before using an API.
- Use the Effect-native APIs: `Brick.action`, `Brick.service`, `Brick.app`, and `Brick.route` from `@brickkit/core`.
- Define input and output schemas with `Schema` from `effect`.
- Declare domain failures as `Schema.TaggedError` classes with `{ httpApiStatus }` annotations.
- Use `@brickkit/crud` with `crudContract` and `sqliteStore` or `postgresStore` for declarative CRUD.
- CRUD requires an explicit access policy: preserve field permissions, `authorize`, and SQL `scope`.
- Handlers return Effects and access dependencies with `yield* Service` inside `Effect.gen`.
- Supply dependencies at the application boundary with `Layer` in `Brick.app({ services, layer })`.
- Keep browser contract modules (`contract.ts`) free of database drivers and server implementations.
- Use `createClient` from `@brickkit/client` for frontend browser calls.
- Run `bun run typecheck`, `bun test`, and lint checks after making changes.
```

Add your own commands, service entry path, and migration rules to make these instructions useful for your project.

## Connect to your application's MCP tools

Brick provides first-class support for Model Context Protocol (MCP) through Effect's native `effect/ai` integration. Register tools directly on actions using `mcp: true` and tool annotations:

```ts title="src/services/tools.ts"
import { Brick } from "@brickkit/core";
import { Schema, Effect } from "effect";

export const searchAction = Brick.action("search", "/api/search", {
  input: Schema.Struct({ query: Schema.String }),
  output: Schema.Array(Schema.String),
  errors: [],
  mcp: true,
  title: "Search Knowledge Base",
  description: "Search documents matching query keywords",
  tool: { readOnly: true },
})((input) => Effect.succeed([`Result for ${input.query}`]));
```

Mount the MCP transport in your application using `Brick.app`:

```ts title="src/app.ts"
import { Brick } from "@brickkit/core";
import { McpProtocol } from "effect/ai";
import { Layer } from "effect";
import { searchService } from "./services/tools";

export default Brick.app({
  services: [searchService],
  layer: Layer.empty,
  transports: {
    mcp: {
      name: "my-app-agent",
      version: "1.0.0",
      path: "/mcp",
      protocols: [McpProtocol.v2025_11_25],
    },
  },
});
```

Point your agent's MCP client at `http://localhost:4000/mcp`. Tool annotations describe behavior, while `authorize` enforces access.

## Generate context from your app

Export the service graph and route metadata from your application:

```bash
bunx brick build src/app.ts
```

The build bundles the application into `dist/brick/server.js` and outputs `dist/brick/brick-ir.json`. The intermediate representation describes all services, actions, HTTP methods, and routes in structured JSON.

Alternatively, introspect your application using:

```bash
bunx brick info src/app.ts > brick-architecture.json
```

Or access the OpenAPI 3.1 specification at runtime by calling `app.openApi()` or visiting the `/reference` documentation endpoint.
