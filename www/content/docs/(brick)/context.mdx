title: Execution Context & Services
description: Resolve request context, inject databases and user authentication, and manage dependencies with Effect Layers.
---

In Brick-TS, execution context and dependencies are managed through Effect's native **`Context.Service`** and **`Layer`** system. Instead of untyped ambient state, every dependency an action requires is tracked at compile time in the Effect's requirement channel (`R`).

## Minimal Example

Define a typed `CurrentUser` service, require it inside an action handler, and supply the dependency with a `Layer`:

```ts title="src/services/billing.ts"
import { Brick } from "@brickkit/core";
import { Unauthorized } from "@brickkit/core/contracts";
import { Context, Effect, Layer, Schema } from "effect";

// 1. Declare the service tag and type
export interface User {
  id: string;
  plan: "free" | "pro";
}

export class CurrentUser extends Context.Service<CurrentUser, User>()(
  "CurrentUser",
) {}

// 2. Action requiring CurrentUser in its Effect environment
export const GetSubscription = Brick.action(
  "getSubscription",
  "/api/billing/subscription",
  {
    input: Schema.Struct({}),
    output: Schema.Struct({ plan: Schema.String }),
    errors: [Unauthorized],
  },
);

export const getSubscription = GetSubscription(() =>
  Effect.gen(function* () {
    const user = yield* CurrentUser;
    return { plan: user.plan };
  }),
);

export const billingService = Brick.service("billing", {
  actions: { getSubscription },
});
```

When composing the application, supply the requirement using a `Layer`:

```ts title="src/app.ts"
import { Brick } from "@brickkit/core";
import { Layer } from "effect";
import { billingService, CurrentUser } from "./services/billing";

// Provide a mock user layer for tests or local execution
const UserLive = Layer.succeed(CurrentUser, { id: "usr_42", plan: "pro" });

export default Brick.app({
  services: [billingService],
  layer: UserLive,
  docs: { path: "/reference" },
});
```

If an action requires `CurrentUser` but `layer` in `Brick.app` does not supply it, **TypeScript will fail to compile**. Missing dependencies are caught before your server ever starts.

## Startup Dependencies vs Request Dependencies

A robust backend distinguishes between two kinds of dependencies:

1. **Startup Dependencies**: Services acquired once at server launch and shared across requests, such as database connection pools, Redis clients, configuration, and secrets.
2. **Request Dependencies**: Context resolved per incoming HTTP request, such as authentication tokens, request tracing headers, and the authenticated user identity.

### 1. Startup Dependencies (Database Pools)

Use `database<Self>()` from `@brickkit/crud` to create a scoped database service:

```ts title="src/db.ts"
import { database } from "@brickkit/crud";
import { drizzle } from "drizzle-orm/node-postgres";
import { Effect, Layer } from "effect";
import pg from "pg";

export interface DatabaseService {}
export const { Service: Database, layer: DatabaseLive } =
  database<DatabaseService>()(
    "Database",
    Effect.acquireRelease(
      Effect.sync(() => {
        const pool = new pg.Pool({
          connectionString: process.env.DATABASE_URL,
        });
        return drizzle(pool);
      }),
      (db) => Effect.sync(() => {}), // pool cleanup on app shutdown
    ),
  );
```

### 2. Request Dependencies (Authentication & Headers)

To extract authentication state from an incoming HTTP request, use `HttpServerRequest.HttpServerRequest` from `effect/http`:

```ts title="src/auth.ts"
import { HttpServerRequest } from "effect/http";
import { Context, Effect, Layer } from "effect";
import { Unauthorized } from "@brickkit/core/contracts";

export interface Session {
  userId: string;
}

export class SessionService extends Context.Service<SessionService, Session>()(
  "SessionService",
) {}

export const SessionLive = Layer.effect(
  SessionService,
  Effect.gen(function* () {
    const request = yield* HttpServerRequest.HttpServerRequest;
    const authHeader = request.headers["authorization"];
    if (!authHeader || !authHeader.startsWith("Bearer ")) {
      return yield* Effect.fail(
        new Unauthorized({ message: "Missing or invalid bearer token" }),
      );
    }
    const token = authHeader.slice(7);
    // Validate token and return session
    return { userId: token === "secret" ? "usr_admin" : "usr_user" };
  }),
);
```

## Composing Application Layers

Use `Layer.merge` and `Layer.mergeAll` to combine multiple services into a single unified application layer:

```ts title="src/app.ts"
import { Brick } from "@brickkit/core";
import { Layer } from "effect";
import { DatabaseLive } from "./db";
import { usersService } from "./services/users";
import { billingService } from "./services/billing";

// Combine all application dependencies
const AppDependencies = Layer.mergeAll(
  DatabaseLive,
  // Other service layers...
);

export default Brick.app({
  services: [usersService, billingService],
  layer: AppDependencies,
  docs: { path: "/reference" },
});
```

## Scoped Resource Lifetime & Graceful Shutdown

When an application is mounted with `Brick.app()`, it manages a private `Scope`:

- `await app.ready()`: Initializes the dependency graph, opens database pools, and starts HTTP listeners.
- `await app.dispose()`: Closes the application scope. In-flight requests are cleanly aborted, and resource finalizers (such as closing database connection pools) run in reverse acquisition order.

```ts title="src/server.ts"
import app from "./app";

await app.ready();
console.log("Application ready.");

const shutdown = async () => {
  console.log("Shutting down gracefully...");
  await app.dispose();
  process.exit(0);
};

process.on("SIGINT", shutdown);
process.on("SIGTERM", shutdown);
```
