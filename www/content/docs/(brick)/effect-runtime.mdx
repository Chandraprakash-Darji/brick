title: Effect Runtime & Scopes
description: Application resource ownership, fiber cancellation, and explicit local execution.

`Brick.app({ services, layer })` composes native protocol Layers around a single closed application dependency graph. Every application owns its resources explicitly within an Effect `Scope`.

## Application Lifecycle (`ready`, `fetch`, `dispose`)

A Brick application is a self-contained, scoped entity:

```ts title="src/server.ts"
import app from "./app";

// 1. Initialize dependencies and layers
await app.ready();

// 2. Serve HTTP requests
const server = Bun.serve({
  port: 4000,
  fetch: (request) => app.fetch(request),
});

// 3. Graceful shutdown handler
const shutdown = async () => {
  server.stop(true);
  await app.dispose();
  process.exit(0);
};

process.on("SIGINT", shutdown);
process.on("SIGTERM", shutdown);
```

### Lifecycle Guarantees

- **`app.ready()`**: Builds the merged dependency graph, initializes connection pools, and prepares the routing pipeline.
- **`app.fetch(request)`**: Executes requests using standard Fetch API primitives.
- **`app.dispose()`**: Cancels in-flight request fibers and closes the application `Scope`, executing finalizers in reverse acquisition order.

## Request Cancellation & Fiber Interruption

In traditional Node/Bun web frameworks, when a client closes their browser tab or cancels a fetch request, the server continues executing database queries and expensive computations in the background, wasting CPU and database capacity.

In Brick-TS, HTTP requests are bound to native Effect fibers and standard `AbortSignal` listeners:

1. When a client aborts an HTTP request, Brick automatically triggers **fiber interruption** on the handler's active fiber.
2. Any active SQL queries, HTTP calls, or async effects stop immediately.
3. Registered Effect finalizers (e.g. `Effect.addFinalizer`) run cleanly, releasing locks and temporary resources.

## Failure Channels vs Defects

Brick maintains a strict separation between expected domain failures and unexpected defects:

### 1. Declared Domain Errors

When a handler returns a declared `Schema.TaggedError`:

- The error is encoded with its declared schema.
- The HTTP response status code matches its `{ httpApiStatus }` annotation (e.g. 404 for `NotFound`).
- The tagged JSON payload (`{ "_tag": "NotFound", "message": "..." }`) is delivered to the client.

### 2. Unexpected Defects (500 Internal Server Error)

When an unexpected exception, unhandled promise rejection, or runtime defect occurs:

- The defect is logged to server telemetry.
- The wire response is automatically redacted to prevent leaking internal stack traces or database connection strings:
  ```json
  {
    "message": "Internal server error"
  }
  ```
- HTTP status code 500 is returned.

## In-Process Execution with Layers

When invoking actions directly in TypeScript without an HTTP server, provide dependencies explicitly using `Effect.provide`:

```ts title="src/scripts/seed.ts"
import { getUser } from "../services/users";
import { UserDatabaseLive } from "../db";
import { Effect } from "effect";

const program = Effect.gen(function* () {
  const user = yield* getUser({ id: "usr_42" });
  console.log("Seeded user:", user.name);
});

// Run directly with the database layer:
await Effect.runPromise(program.pipe(Effect.provide(UserDatabaseLive)));
```
