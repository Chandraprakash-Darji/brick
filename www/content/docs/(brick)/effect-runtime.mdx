## Runtime bindings

Each `brick()` call builds one `ManagedRuntime` and binds it to every service it owns. Direct calls (`action.run`, `executeEffect`, MCP `callTool`) resolve dependencies through the bound runtime. `app.handle` runs inside the app runtime instead.

Services can be shared across apps. The newest live binding wins for direct calls. Disposing an app restores the previous binding. A failed `initialize()` also unbinds before it disposes its runtime.

## Disposal and handle lifetime

`dispose()` runs service destruction hooks, releases the `Layer`, and releases each database handle the app acquired at construction. A handle closes only after the last app that acquired it is disposed.

The rules, in order:

- Handles are acquired after `brick()` succeeds. A construction failure acquires nothing and closes nothing.
- Each app releases exactly the handles it acquired, at most once. A handle installed later with `setDb` belongs to whoever installed it.
- A failed `initialize()` releases the acquired handles and unbinds the services.

## Error mapping

Typed errors pass through unchanged. Anything else becomes a redacted `500`.

- `authorize: false` fails with `UNAUTHORIZED` (`401`) when `ctx.user` is missing and `FORBIDDEN` (`403`) otherwise.
- A thrown `ActionExecutionError` or `ValidationError` keeps its code, status, and message.
- Any other thrown or rejected value becomes `INTERNAL_SERVER_ERROR` (`500`) with the message `"Internal Server Error"`. The framework logs the original value with the request id.
- An explicit `Effect.fail(value)` passes `value` through the action boundary unchanged, including across the Promise boundary.
- An `Effect` defect (`Effect.die`) becomes `INTERNAL_SERVER_ERROR` (`500`) at the action boundary.
