Brick-TS uses whatever primary key your Drizzle table defines: autoincrement integers, UUIDs, or custom prefixed string identifiers minted with `$defaultFn()`.

## Minimal Example

Define an auto-minted UUID primary key in Drizzle and register it with `crudContract`:

```ts title="src/services/items.ts"
import { Brick } from "@brickkit/core";
import { crudContract, sqliteStore } from "@brickkit/crud";
import { sqliteTable, text } from "drizzle-orm/sqlite-core";
import { ItemsDb } from "./db";

export const items = sqliteTable("items", {
  // Auto-minted UUID primary key
  id: text("id")
    .primaryKey()
    .$defaultFn(() => crypto.randomUUID()),
  name: text("name").notNull(),
});

// 1. Declare the CRUD contract with the primary key field name
export const itemContract = crudContract({
  name: "item",
  path: "/api/item",
  table: items,
  id: "id",
  errors: [],
  fields: {
    id: { read: true, filter: ["eq", "in"] },
    name: { read: true, create: true, update: true },
  },
});

// 2. Implement the actions
export const itemActions = itemContract.implement({
  store: sqliteStore(items, ItemsDb),
  access: "public",
});

export const itemsService = Brick.service("items", {
  actions: itemActions,
});
```

## Primary Key Strategies

### 1. Auto-Minted UUIDs

Using UUIDs generated in application code avoids sequential guessing attacks and lets clients generate valid IDs offline:

```ts
import { sqliteTable, text } from "drizzle-orm/sqlite-core";

export const documents = sqliteTable("documents", {
  id: text("id")
    .primaryKey()
    .$defaultFn(() => crypto.randomUUID()),
  title: text("title").notNull(),
});
```

### 2. Autoincrement Integers

For internal catalogs or high-volume append-only sequences:

```ts
import { sqliteTable, integer, text } from "drizzle-orm/sqlite-core";

export const logs = sqliteTable("logs", {
  id: integer("id").primaryKey({ autoIncrement: true }),
  message: text("message").notNull(),
});
```

Pass `id: "id"` into `crudContract({ table: logs, id: "id", ... })`. Brick automatically derives an integer schema for route inputs, so `log.get({ id })` requires a number.

### 3. Custom Prefixed Identifiers (e.g. `usr_...`, `inv_...`)

Prefixed IDs improve readability in logs and API debugging:

```ts
export const users = sqliteTable("users", {
  id: text("id")
    .primaryKey()
    .$defaultFn(() => `usr_${crypto.randomUUID().slice(0, 8)}`),
  email: text("email").notNull(),
});
```

## How Routes Use Primary Keys

When `crudContract` creates endpoints, the primary key column dictates the schema for individual row operations:

- **Get Row** (`page.get`): Accepts `{ id }`. Fails with `NotFound` (404) if the row doesn't exist.
- **Update Row** (`page.update`): Accepts `{ id, data }`. Applies changes only to the matching row.
- **Delete Row** (`page.delete`): Accepts `{ id }`. Removes the row and returns `{ success: true }`.

### Batch Fetching with `in`

To fetch multiple records by ID in a single query, enable the `in` filter operator on the primary key:

```ts
fields: {
  id: { read: true, filter: ["eq", "in"] },
}
```

Then query via `page.list`:

```bash
curl -X POST http://localhost:4000/api/page/list \
  -H "Content-Type: application/json" \
  -d '{
    "where": {
      "field": "id",
      "op": "in",
      "value": ["id_1", "id_2", "id_3"]
    }
  }'
```
