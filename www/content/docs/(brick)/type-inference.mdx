Brick-TS delivers instant, bidirectional type safety by deriving static TypeScript types directly from runtime Effect Schemas and Drizzle database models without intermediate compilation steps.

## Minimal Example

Derive static TypeScript types directly from schemas and tables without running codegen commands:

```ts title="src/types/models.ts"
import { Schema } from "effect";
import { sqliteTable, text } from "drizzle-orm/sqlite-core";
import type { InferInsertModel, InferSelectModel } from "drizzle-orm";

// 1. Runtime validation schema -> TypeScript static type
export const UserSchema = Schema.Struct({
  id: Schema.String,
  name: Schema.String,
  role: Schema.Literals(["admin", "member"]),
});

export type User = typeof UserSchema.Type;
// Equivalent to: { id: string; name: string; role: "admin" | "member" }

// 2. Drizzle table -> Select and Insert types
export const users = sqliteTable("users", {
  id: text("id")
    .primaryKey()
    .$defaultFn(() => crypto.randomUUID()),
  name: text("name").notNull(),
  bio: text("bio"),
});

export type UserRow = InferSelectModel<typeof users>;
export type NewUserRow = InferInsertModel<typeof users>;
```

## Why Zero-Codegen Matters

Many backend frameworks rely on external DSLs, generated code directories (`gen/`, `prisma/client`), or background file watchers. Brick-TS avoids code generation:

1. **Instant Feedback**: When you add a field to a Drizzle table or an Effect Schema, types update in your editor immediately.
2. **Zero Drift**: Client and server types are mathematically derived from the exact same contract definitions.
3. **No Intermediate Files**: There are no out-of-sync generated TypeScript files to commit, ignore, or clean up.

## Deriving Action and CRUD Input Types

When defining clients or frontend components, you can derive exact input types directly from contracts:

```ts title="src/api/contract.ts"
import { crudContract } from "@brickkit/crud";
import { pagesTable } from "./schema";

export const pageContract = crudContract({
  name: "page",
  path: "/api/page",
  table: pagesTable,
  id: "id",
  errors: [],
  fields: {
    id: { read: true },
    title: { read: true, create: true, update: true },
    content: { read: true, create: true, update: true },
  },
});

type PageActions = typeof pageContract.actions;

/** Request payload for creating a page */
export type PageCreateInput =
  PageActions["page.create"]["endpoint"]["~Payload"]["Type"];

/** Request envelope for updating a page */
export type PageUpdateRequest =
  PageActions["page.update"]["endpoint"]["~Payload"]["Type"];

/** Update data payload */
export type PageUpdateInput = PageUpdateRequest["data"];
```

When the database schema or field policy changes on the server, TypeScript immediately updates `PageCreateInput` and `PageUpdateInput` across your frontend codebase.

## Typed Clients without Codegen

When consuming your API through `@brickkit/client`:

```ts
import { createClient } from "@brickkit/client";
import { Api, type PageCreateInput } from "./contract";

const { client } = createClient(Api, { baseUrl: "http://localhost:4000" });

// Autocomplete and compile-time type validation for parameters and return types:
const newPage = await client.page["page.create"]({
  payload: {
    title: "New Page",
    content: "Markdown body...",
  },
});
```

The method name, parameter shape, and response type are all inferred from `Api` without code generation.
