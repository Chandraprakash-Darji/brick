Brick-TS provides first-class support for AI agents through Effect's native `effect/ai` Model Context Protocol (MCP) integration.

## Minimal Example

Declare an action with `mcp: true` and tool behavior annotations, then mount the MCP transport in your application:

```ts title="src/services/documents.ts"
import { Brick } from "@brickkit/core";
import { NotFound } from "@brickkit/core/contracts";
import { Effect, Schema } from "effect";

// 1. Declare an action with MCP tool metadata
const SearchDocs = Brick.action("search_docs", "/api/docs/search", {
  input: Schema.Struct({
    query: Schema.String.annotate(
      Schema.Description,
      "Search terms or keywords",
    ),
    limit: Schema.optionalKey(Schema.Number),
  }),
  output: Schema.Array(
    Schema.Struct({
      id: Schema.String,
      title: Schema.String,
      snippet: Schema.String,
    }),
  ),
  errors: [NotFound],
  mcp: true,
  title: "Search Knowledge Base",
  description: "Search documents matching query keywords",
  tool: {
    readOnly: true,
    idempotent: true,
  },
});

// 2. Implement the Effect handler
export const searchDocs = SearchDocs(({ query, limit }) =>
  Effect.succeed([
    {
      id: "doc_1",
      title: "Architecture",
      snippet: "Brick-TS is built on Bun and Effect...",
    },
  ]),
);

export const docsService = Brick.service("docs", {
  actions: { searchDocs },
});
```

Mount the MCP server in `src/app.ts`:

```ts title="src/app.ts"
import { Brick } from "@brickkit/core";
import { McpProtocol } from "effect/ai";
import { Layer } from "effect";
import { docsService } from "./services/documents";

export default Brick.app({
  services: [docsService],
  layer: Layer.empty,
  transports: {
    mcp: {
      name: "docs-agent-server",
      version: "1.0.0",
      path: "/mcp",
      protocols: [McpProtocol.v2025_11_25],
    },
  },
  docs: { path: "/reference" },
});
```

When started, your application serves standard HTTP REST endpoints on `/api/...` and mounts an MCP server on `/mcp`.

## Tool Behavior Annotations (`tool`)

AI agents like Claude Code, Cursor, and Copilot use tool behavior annotations to determine when to call tools automatically and whether to prompt the user for confirmation:

| Property      | Type      | Default | Description                                                                    |
| :------------ | :-------- | :------ | :----------------------------------------------------------------------------- |
| `readOnly`    | `boolean` | `false` | When `true`, indicates the tool only queries data and does not modify state.   |
| `destructive` | `boolean` | `false` | When `true`, indicates the tool performs irreversible actions (e.g. deletion). |
| `idempotent`  | `boolean` | `false` | When `true`, calling the tool multiple times produces the identical outcome.   |
| `openWorld`   | `boolean` | `false` | When `true`, indicates the tool interacts with external systems or web APIs.   |

## MCP Protocol Support

Brick's native MCP integration uses `effect/ai` and supports modern protocol specifications:

- `McpProtocol.v2025_11_25`: Modern MCP specification with session negotiation, capability exchange, and structured tool parameter validation.

Tools validate input parameters using the exact same Effect Schema that governs HTTP requests. If an AI agent sends invalid arguments, the MCP server returns a standard protocol error before the handler executes.

## Securing MCP Endpoints

To authenticate agents accessing `/mcp`, add bearer token verification or OAuth protected resource metadata using `Brick.route`:

```ts title="src/routes/oauth.ts"
import { Brick } from "@brickkit/core";
import { HttpServerResponse } from "effect/http";
import { Effect } from "effect";

export const oauthMetadata = Brick.route(
  "GET",
  "/.well-known/oauth-protected-resource",
  Effect.sync(() =>
    HttpServerResponse.jsonUnsafe({
      authorization_servers: ["https://auth.example.com"],
      resource: "https://api.example.com/mcp",
    }),
  ),
);
```

You can guard the `/mcp` route with authentication middleware using Effect's `HttpRouter` or `@better-auth/mcp`.

## Monomorphic Execution

Because actions in Brick-TS are monomorphic:

- The tool can be called by an AI agent over MCP.
- The same tool can be invoked over HTTP POST at `/api/docs/search`.
- The same tool can be called in-process by other services as an `Effect`.

All three call sites share identical schema validation and declared errors. Each transport renders failures in its own format: HTTP denies with a status code (for example 403), RPC surfaces a typed failure, and MCP returns a tool result with `isError: true`. Authorization depends on the action's Effect requirements and the authentication layer configured for each transport.
