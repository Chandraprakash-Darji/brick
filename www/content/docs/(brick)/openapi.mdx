Brick-TS serves its OpenAPI 3.1 spec **live** from the running server — there is no offline emission step and no static spec file to check in.

## Generating the spec in code

```ts
import { generateOpenApiSpec } from "@brickkit/core";

const spec = generateOpenApiSpec({
  title: "Pages API",
  version: "1.0.0",
  description: "Public pages service",
  prefix: "/api",
  services: [pagesService], // defaults to every registered service
});
```

Options: `title` (default `"Brick-TS API Mesh"`), `version` (`"1.0.0"`), `description`, `prefix` (`"/api"`), `services`, `registry`. Each action exposes one operation at its configured `path` (default `/api/{service}/{action}`) and `method` (default `POST`). Custom paths replace the default action path; action names do not infer extra methods. Path parameters are documented as required parameters; `GET` and `DELETE` use query parameters for the remaining input. Actions with `authorize` advertise `bearerAuth`; per-action `errors:` entries become named response schemas.

## Served paths

`brick` wires these automatically (all paths configurable via options):

| Path                   | Content                                      |
| ---------------------- | -------------------------------------------- |
| `GET /openapi.json`    | The generated spec (raw endpoints merged in) |
| `GET /docs`            | Scalar API reference (HTML)                  |
| `GET /swagger`         | Swagger UI (HTML)                            |
| `GET /_brick/services` | Architecture JSON (`exportArchitecture()`)   |

```ts
const app = brick({
  services: [pagesService],
  title: "Pages API",
  version: "1.0.0",
  // openApiPath: "/openapi.json", docsPath: "/docs", swaggerPath: "/swagger",
  // docs: true, reference: false, // optional /reference page
});
```

Need a static snapshot for SDK generation? Fetch `/openapi.json` from a running instance in CI and save the result — the generator itself always runs against live service registrations.

First-party frontends usually don't need the spec at all: the [Typed Client](/docs/typed-client) infers inputs, outputs, and error codes straight from your TypeScript contract with no codegen step.
