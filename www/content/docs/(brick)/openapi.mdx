title: OpenAPI 3.1 & Interactive Documentation
description: Generate OpenAPI 3.1 specifications and serve interactive Scalar API docs automatically.
---

Brick-TS automatically generates compliant OpenAPI 3.1 JSON specifications from Effect Schema contracts and serves interactive documentation via Scalar.

## Minimal Example

Enable automatic interactive documentation by passing `docs: { path: "/reference" }` into `Brick.app`:

```ts title="src/server.ts"
import { Brick } from "@brickkit/core";
import { NotFound } from "@brickkit/core/contracts";
import { Effect, Layer, Schema } from "effect";

const GetUser = Brick.action("getUser", "/api/users/getUser", {
  input: Schema.Struct({ id: Schema.String }),
  output: Schema.Struct({ id: Schema.String, name: Schema.String }),
  errors: [NotFound],
  title: "Get User Profile",
  description: "Retrieve a user by unique identifier",
});

const getUser = GetUser(({ id }) =>
  Effect.succeed({ id, name: "Ada Lovelace" }),
);

const usersService = Brick.service("users", {
  actions: { getUser },
});

export const app = Brick.app({
  services: [usersService],
  layer: Layer.empty,
  docs: { path: "/reference" },
});

export default app;
```

When started with `bunx brick dev src/server.ts`, visit:

- **Scalar Interactive UI**: `http://localhost:4000/reference`

## Schema and Operation Annotations

You can enrich the generated OpenAPI documentation with titles, descriptions, and tags using Schema annotations:

```ts title="src/schemas/user.ts"
import { Schema } from "effect";
import { OpenApi } from "effect/http-api";

export const UserSchema = Schema.Struct({
  id: Schema.String.annotate(OpenApi.Description, "Unique user identifier"),
  name: Schema.String.annotate(OpenApi.Description, "Display name"),
  email: Schema.String.annotate(OpenApi.Description, "Verified email address"),
}).annotate(OpenApi.Title, "User Profile");
```

## Status Codes from Tagged Errors

Brick maps declared `Schema.TaggedError` classes to their respective HTTP status codes in the generated OpenAPI schema. Because each error specifies its status via `{ httpApiStatus: ... }`, OpenAPI clients know exactly what error envelope to expect for each HTTP response code:

- `NotFound` (`{ httpApiStatus: 404 }`) -> Documented under HTTP 404
- `Unauthorized` (`{ httpApiStatus: 401 }`) -> Documented under HTTP 401
- `Forbidden` (`{ httpApiStatus: 403 }`) -> Documented under HTTP 403
- `BadRequest` (`{ httpApiStatus: 400 }`) -> Documented under HTTP 400

## Programmatic OpenAPI Generation

In code or build scripts, you can generate the raw OpenAPI 3.1 JSON document directly from your application:

```ts title="src/generate-spec.ts"
import app from "./server";

const openApiDocument = app.openApi();
console.log(JSON.stringify(openApiDocument, null, 2));
```

## Generating Specs via the CLI

Extract the OpenAPI 3.1 specification to a file using the `brick` CLI:

```bash
bunx brick gen openapi src/server.ts --output openapi.json
```
