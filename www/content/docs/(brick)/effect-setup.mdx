Brick-TS is built from the ground up as an Effect-native framework. Business actions, CRUD operations, database handles, error envelopes, and AI tools are all first-class Effect programs.

## Dependencies

Install the Brick packages and `effect`:

```bash
bun add @brickkit/core @brickkit/crud @brickkit/client @brickkit/cli effect drizzle-orm
```

Brick-TS is designed for `effect@4.x`.

## TypeScript Configuration

Effect leverages advanced TypeScript features for precise type inference and compile-time requirement checking. Ensure your `tsconfig.json` includes:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "skipLibCheck": true,
    "noEmit": true
  }
}
```

## Core Effect Modules in Brick

When building applications with Brick-TS, you will interact with the following Effect modules:

| Module            | Role in Brick-TS                                                                         |
| :---------------- | :--------------------------------------------------------------------------------------- |
| `effect/Effect`   | Pure computations, async control flow, typed errors (`E`), and requirements (`R`).       |
| `effect/Schema`   | Runtime input and output validation, schema refinements, and tagged error classes.       |
| `effect/Context`  | Declaring dependency tags via `Context.Service` for compile-time dependency injection.   |
| `effect/Layer`    | Assembling and composing dependencies (database pools, auth services) into applications. |
| `effect/http-api` | Transport definitions, OpenAPI 3.1 generation, and HTTP client infrastructure.           |
| `effect/ai`       | Model Context Protocol (MCP) server protocols and tool behavior annotations.             |

## Recommended Project Structure

An Effect-native Brick application separates contract declarations from server implementations:

```text
my-brick-app/
├── src/
│   ├── contract.ts       # Browser-safe contracts (Schema, HttpApi, errors)
│   ├── schema.ts         # Drizzle database tables
│   ├── db.ts             # Database service tag and acquisition layer
│   ├── services/
│   │   ├── users/        # Action handlers and service definitions
│   │   └── pages/        # CRUD implementations and hooks
│   ├── app.ts            # Brick.app() composition with Layer
│   └── client.ts         # Frontend createClient re-export
├── tsconfig.json
└── package.json
```

By keeping `src/contract.ts` free of database drivers and server dependencies, you can import it into frontend applications or generate client wrappers with `brick gen client` without bundle pollution.
